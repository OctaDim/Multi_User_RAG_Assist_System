## Изменённое поведение

- Каждый полный стартовый блок проверяется на порядок START common → START project
  → rules → INDEX common → INDEX project. Неверный порядок даёт отказ без перестановки.
  Отдельно восстанавливается однозначный повтор с несколькими потерянными ссылками.
  Частичный блок требует минимум трёх разных canonical labels/targets в правильном
  относительном порядке; маленькие/произвольные списки не расширяются догадками.
- Общий line classifier исключает fences верхнего уровня, вложенных цитат и одного
  элемента списка, включая quoted list, а также inline/indented code. Согласованы
  глубина цитирования, отступ списка, символ/длина закрытия. Неоднозначные контейнеры
  и незакрытый текущий fence дают отказ; исторический незакрытый пример идёт до EOF.
  Полный Markdown parser и рекурсивные list-item контейнеры не добавлены.
- До ремонта проверяются непустые строгие UTF-8 START/INDEX, полный ordinary/equal
  canonical/native comm-/proj- набор и доступность вложенных rule-каталогов.
  Пропуски, extra canonical copies, различия, пустой текст и симлинки дают отказ.
  Личные правила и human guides не считаются extra canonical. Правила не публикуются
  автоматически. Владелец проверки копий перенесён из test helper в тот же common
  скрипт; тест импортирует его, нового вспомогательного скрипта нет.
- Снимок входа включает bytes, identity, timestamps, size, owner и mode. Обнаруженная
  параллельная правка при планировании или перед replace сохраняется. Запись идёт
  через временный файл в той же папке, flush/fsync и atomic replace, с сохранением
  existing owner/mode и поддерживаемых xattrs/ACL. Сбой метаданных запрещает replace.
  Временный файл очищается; ошибка сообщает выполненные и ещё планируемые операции.
  Существующие LF/CRLF и пользовательский текст вне разрешённых вставок сохраняются.
