# Человеческие пояснения

До поиска/чтения/подключения контекста исключи README.human.md на любой глубине:
это человеческие пояснения, не агентские инструкции. Не загружай тела в старт,
индексы, импорты, description, общий cat или сборщики; при поиске используй
-g '!README.human.md'. Для cat передавай только явно перечисленные машинные Markdown из списка,
уже исключающего README.human.md. Глоб *.md не выражает исключение, даже если
README сейчас нет.
Личная процедура не отменяет исключение.

Для полного чтения правил сначала отдельным вызовом инструмента получи список:
`rg --files --hidden --no-ignore .claude/rules -g '*.md' -g '!README.human.md'`.
После получения списка следующим отдельным вызовом передай cat каждый найденный
путь явно и в кавычках. Не используй glob и не ограничивай список префиксами
comm-/proj-: нужны все машинные правила, включая вложенные и игнорируемые.
При обрезанном выводе дочитай остаток; полные результаты чтения всех правил
должны быть получены до открытия скиллов.

Согласованные категории создавай заранее, даже пустые; каждой новой папке
harness сразу нужен README.human.md с простым пояснением и понятным примером
(в пустой — иллюстративным). Наличие README не доказывает наполненность/проверку.
Программная проверка может читать тела, возвращая только пути/ошибки/результат.

Для оценки инструкций до запуска инструментов открой
`harness/common/skills/comm-validate-harness-instructions/SKILL.md`:
там процедура human-фильтра и отдельных проверок чтения, загрузчиков и поведения.
