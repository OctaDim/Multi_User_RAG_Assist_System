# Choose the result

First name the behavior needed in the next similar case. Inspect descriptions,
applicable rules, then only relevant bodies/resources/executable checks.
Covered behavior: reuse/improve the owner; if already fully expressed, no record.
Independent repeatable request/result/check with recognizable trigger: lazy skill,
not a branch justified by theme/old owner name. No skill-count quota.
Same-result details/examples: owner resource with tested when-read pointer.
Rule: name the wrong action possible before skill selection; a mandatory
algorithm alone is not an always-loaded rule. Early guards remain in rules.

Check existing fixes/tests: they do not themselves replace instructions.
Keep only essential reasons/evidence separately; no error story in SKILL and
no additional router. Procedure belongs to skills/resources; early limits to rules.
Decisions/contracts/invariants/limitations/essential alternatives → decisions;
results/check limitations/raw evidence → testing/evidence; basic config → base;
specifications → specs; explanations/research → docs; plans → docs/plans;
unfinished state → handoffs. Inbox is temporary full request/candidate.
Docs/decisions/specs/evidence are reasons/formal contracts, not independent
agent procedures. Before placement read the own material-placement resource.
