# Preserve useful knowledge

Establish future behavior/useful result and the intended harness; cwd alone
is insufficient. Before choosing a form read
[experience routing](references/experience-routing.md).

1. Inspect existing descriptions/rules, then only relevant bodies/resources/checks.
   Fully covered → reuse without a record. Independent request/result/check →
   suitable owner; same-result detail → conditional resource.
2. Select common/project by content and the permanent category. Keep procedure
   with one skills/rules owner; retain essential rationale/evidence separately.
3. Before placement or date migration read
   [material placement](references/material-placement.md). Preserve unknown dates.
4. Before any write follow the authorized inbox route from project root
   `harness/common/skills/comm-process-harness-inbox/SKILL.md`.

Completion: useful behavior is covered once, material lives in the appropriate
permanent category independently of inbox, valid dates/links/resources and
actual checks/statuses are recorded. New instruction design uses
`harness/common/skills/comm-create-lazy-claude-codex-skills/SKILL.md` only when needed.
