# Сохранение исходных байтов при восстановлении входных ссылок

Дата: 2026-10-05. Python: 3.12.3. Область: техническая проверка входов,
её автономная project-копия и регрессионные тесты. Правила и скиллы не изменены.

## Контекст и разрешение

Пункт 2 аудита: восстановление ссылки нормализовало существующие CRLF в LF.
Пользователь выбрал пункт и явно ответил «да» на предложение создать заявку
о сохранении CRLF и выполнить только её. Создание и обработка этой заявки разрешены.
Корневые AGENTS.md/CLAUDE.md при выполнении не изменялись; тестовые входы
создавались только во временных проектах. Предшествующее исправление fenced-кода сохранено.

Причина: Path.read_text нормализовал переводы строк; Path.write_text записывал
изменённое содержимое. Распознавание импорта и исключение сгенерированных строк
при сравнении с Git также предполагали LF.

## Итоговое поведение

- Чтение и запись UTF-8 выполняются через байты без нормализации переводов строк.
- AGENTS.md получает отсутствующие подключения после исходного содержимого;
  исходные завершающие пустые строки также сохраняются.
- Импорт в CLAUDE.md добавляется перед исходным содержимым. Для вставок используется
  первый существующий перевод LF/CRLF каждого отдельного файла; без него — LF.
  Существующие смешанные переводы строк не нормализуются.
- Единственный импорт с CRLF распознаётся как исправный. Повторный запуск
  не дублирует импорт, не записывает файлы и не предупреждает о ложном повреждении.
- Сгенерированные строки CRLF корректно исключаются из сравнения с Git;
  восстановление ссылок не выдаётся за изменение пользовательских настроек.
