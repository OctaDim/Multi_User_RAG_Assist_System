The installation contract distinguishes these cases:

- **Wholly absent project, including after deletion:** mandatory startup creates a fresh neutral `harness/project` from the agreed `project-skeleton.json`, including categories, START/INDEX, human guides, and `testing/evidence/work/` and `testing/evidence/harness/`. No inbox request or extra confirmation is required for this narrow exception. Deleted history is **not restored**.
- **Two supported modes:** common-only creates that absent neutral project; common+project preserves the existing project byte-for-byte. Common is mandatory; project-only is unsupported.
- **Existing project:** startup neither replaces it nor extends it from a newer template. Legacy folders remain.
- **Partially missing categories or guides:** the project still counts as existing, so startup preserves it without filling gaps. Repairs require specifically authorized scope.
- **Missing START/INDEX in an existing project:** startup fails before writes. Restoring entrypoint links does not recreate missing target documents; the template is not a recovery backup.

Application evidence belongs under `work/`; project mechanism evidence belongs under `harness/`. Authorized ordinary application documentation can go directly into permanent project categories, preserving its actual status. That authorization does not cover mechanism edits, migrations, cleanup, or protected bypasses.
