# Компактное создание скиллов и правил

Обязательный порядок common harness. Установлен пользователем 2026-10-05.
Применяется при создании и изменении скиллов и правил, в том числе при обработке inbox.

## Выбор формата нового материала

Для новых материалов правильный исходный выбор — **контекстный lazy-скилл**, если есть
распознаваемый сценарий применения. Постоянный rule требует отдельного обоснования:
какое ошибочное действие возможно *до выбора этого скилла*. Создание новой заявки
само по себе не является поводом добавлять постоянное правило.

## Последовательность

1. Зафиксировать сохраняемый контракт: условия применения, обязательные ограничения,
   действия и требуемый результат. Указать сценарии, по которым проверяется поведение.
2. Выполнить RED: исходный прогон поведения без нового скилла или правила показывает
   ошибку, которую инструкции должны исправить. Это отдельная проверка исходного
   поведения; длинный промежуточный черновик для неё не нужен.
3. Сразу готовить компактную версию. Оценить объём, убрать повторы и лишний текст,
   подробности вынести в ресурсы, открываемые по необходимости. SKILL.md содержит
   условия применения и необходимую процедуру; always-loaded правило — короткие
   обязательные границы, процедура и детали открываются по текущей задаче.
4. Проверить итоговый комплект: формат выбранного артефакта, ссылки и ресурсы,
   стоимость загрузки, сценарии поведения и сохранение контракта. GREEN подтверждает
   исправление наблюдавшейся ошибки и сохранение остальных обязательных сценариев.
5. Если после проверки изменены инструкции или ресурсы, включая дальнейшее сжатие,
   повторить проверки и сценарии поведения для итоговой версии. При изменении
   условий применения или маршрутизации повторить соответствующие проверки выбора
   и загрузки деталей. REFACTOR завершается проверкой уже изменённого материала.

Полная проверка промежуточного длинного черновика обычно не требуется. Если материал
уже компактен, искусственно сокращать его повторно не нужно: оценка фиксирует, что
лишнего текста нет, а проверка выполняется для существующей компактной версии.

## Сохранение поведения

Сжатие не разрешает удалять условия применения, запреты, согласования, существенные
шаги, требуемые результаты или ресурсы. Перенос подробностей сохраняет понятный
указатель: когда открыть ресурс и какой файл содержит нужную информацию. Указатель
и доступность ресурса проверяются вместе с выполнением соответствующего сценария.
Нельзя добиться меньшего объёма заменой необходимой инструкции неоднозначной фразой.

Пример: запрет публикации непроверенного скилла без явного разрешения остаётся
короткой обязательной границей. Команды проверок и устройство отчёта открываются
при создании или публикации. Проверяются оба сценария: публикация без разрешения
не выполняется; явно разрешённое исключение сохраняет статус «непроверен».

## Стоимость и отметка проверки

Отдельно оценивать стартовые инструкции, name/description, тело выбранного скилла
и ресурсы, фактически открываемые по сценарию. Сумма размеров всех файлов не равна
стоимости начальной загрузки. Указать метод оценки; статическую оценку токенов
не выдавать за измеренный расход сессии. README.human.md исключать из чтения и контекста.

Для каждого скилла и правила фиксировать два независимых статуса. Например:

```text
Codex — проверено
Claude — не проверено
Итог — не полностью проверено
```

«Проверено» у конкретного агента означает успешные применимые обязательные проверки
**уже компактной версии**, включая реальные сценарии этого агента и сохранение
обязательного поведения. Само сжатие, валидный формат, меньший размер или успех
другого агента этого не доказывают. Если агент не запускался, отсутствуют инструменты,
данные или успешные сценарии, его статус — «не проверено» с указанием причины.

Полностью проверенным материал считается только при «Codex — проверено» **и**
«Claude — проверено» для одной итоговой версии, с успешными общими обязательными
проверками. В отчёте отдельно отражать результаты каждого из трёх режимов установки;
непроверенный обязательный режим не позволяет выставить успешный итог агенту.
Любая последующая правка инструкций или ресурсов отменяет оба прежних статуса
для изменённой версии до повторной проверки.

Без полной проверки перенос из inbox в канонические `harness/common/skills/`,
`harness/project/skills/` или соответствующие `rules/`, затем в нативные папки
разрешён только с **явным разрешением и подтверждением пользователя** на перенос
при указанных непроверенных результатах. Это относится и к прямому каноническому
созданию: указание создать материал не является разрешением обойти проверку.
До согласования подготовленный материал остаётся в inbox. Согласованное исключение
сохраняет реальные статусы и не делает материал полностью проверенным.

В отчёте сохранить объект/версию, дату, версию и способ запуска каждого агента,
оба статуса и их доказательства или причины непроверенности, сохраняемый контракт,
метод и результаты оценки объёма, проверки и сценарии, оставшиеся ограничения.
При переносе без полной проверки сохранить явное разрешение и подтверждение
пользователя с областью разрешённого переноса. Полный длинный черновик и его проверка
не являются обязательными артефактами отчёта.

Размещение, приоритет и согласования сохраняются по [контракту владения](../rules/comm-skill-rule-ownership.md).
