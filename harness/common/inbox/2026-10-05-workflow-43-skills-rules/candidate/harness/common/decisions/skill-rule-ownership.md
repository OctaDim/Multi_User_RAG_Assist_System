## Решение и причины

После вопроса о переносимости пользователь закрепил канонический источник внутри common/project и обычные нативные копии. Предложение хранить общие скиллы только в корневых нативных каталогах заменено этим решением. Переносимый пакет сохраняет оригиналы; установленные копии обеспечивают обнаружение обоими агентами и восстанавливаются из оригинала.

Явно выбранный индивидуальный режим допускает личный скилл без общего префикса. Без явного канонического указания также обязательна отдельная датированная inbox-заявка с контекстом, требуемым результатом и полной папкой самого скилла; личное размещение её не заменяет. Такие материалы исключаются через .gitignore. Это исключение из прежней границы «все агентские материалы только внутри harness»; оно не разрешает выносить журнал сессии, handoff или общую память в личные скиллы.

Общий опыт по умолчанию проходит подтверждённый inbox и отдельную пользовательскую сессию обработки. Явное указание создать канонический материал внутри harness допускает прямое создание с обязательными проверками; оно не разрешает непроверенную публикацию без отдельного явного исключения. Причина: индивидуальное удобство не должно автоматически становиться обязательством всех разработчиков.

Последующая директива пользователя распространила эту модель на always-loaded rules. Для индивидуальных и установочных правил сохраняется схема .claude/rules/octadim/ из выбранного авторского скилла: один файл, без Codex-зеркала и симлинков. Общие правила сохраняются в Git вместе с каноническим harness; прежнее требование исходного скилла исключать канонические правила через .git/info/exclude не переносится на общие материалы.

Точные размещение, префиксы, согласование и проверки — в [подробном контракте](../docs/skill-rule-ownership-contract.md). Существующие три общих правила переименованы с comm-, их живые ссылки обновлены. Старые имена в датированных наблюдениях обозначают исходный эксперимент, а не текущий обязательный ресурс.

## Карта материалов

| Материал | Категория |
|---|---|
| Критическое ограничение до выбора процедуры | Короткая стартовая инструкция; по возможности механическая защита |
| Повторяемая процедура или предметная компетенция | Самостоятельная папка скилла |
| Решение и его основания | decisions/ |
| Ошибка, причина и проверенное решение | lessons/ |
| Базовый контракт или конфигурация | base/ |
| Незавершённая задача | handoffs/ |

Индекс показывает категории и папки, без списка всех файлов. Например, урок http-retry.md находится поиском в lessons/; добавление урока не требует правки индекса. Метаданные скиллов дают нативный каталог. Дополнительные категории создаются при реальной необходимости; подробный каталог генерируется из метаданных, если он действительно нужен.

## Границы выполненного

Это согласованная модель владения и маршрутизации. Установка авторских скиллов, нативная загрузка правил, обнаружение скиллов, механическая защита приоритета, формат подключения и численные бюджеты ещё не проверены или не завершены. Сам префикс не меняет иерархию инструкций платформы. Проверка файлов не заменяет [приёмку у обоих агентов](../checks/acceptance.md).
