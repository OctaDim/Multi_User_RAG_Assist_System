Закрепи в harness для скиллов и правил следующие требования:
- Инструкция должна однозначно определять применимость, обязательное поведение и проверяемый результат либо сохраняемое условие, существенные ограничения, согласования и условия остановки.
- Необходимые ресурсы доступны; понятно, когда их открыть.
- Форма и объём выбираются по задаче: обязательных заголовков нет, повторять уже выраженное требование не нужно.
- Писать краткие инструкции. При сжатии полностью сохранить поведение, оставляя только информацию, которая помогает агенту принять правильное решение.
- Загрузка деталей по необходимости.

Общие требования к содержанию скиллов и правил:
1. Применимость понятна. Указан сценарий, область действия или условие применения. Если материал действует всегда в своей области, этого достаточно. Уже понятное из метаданных условие не нужно повторять отдельным разделом.
2. Требуемое поведение однозначно. Указано действие, ограничение или сохраняемое условие. Фиксированная последовательность обязательна только там, где порядок влияет на правильность.
3. Соблюдение проверяемо. Понятно, какой результат или поведение считается правильным. Отдельный раздел о нарушении нужен только тогда, когда нарушение нельзя однозначно вывести из требования.
4. Существенные границы сохранены. Указываются относящиеся к задаче запреты, условия остановки, необходимые согласования и поведение при недостаточных данных. Не добавляются предположительные ограничения для посторонних задач.
5. Зависимости доступны. Для необходимых ресурсов и инструментов указаны способ обращения и условие использования. Пути работают после установки; специфичные для платформы действия описываются отдельно.
6. Каждый фрагмент оправдывает своё присутствие. История возникновения, отчёты проверок и подробные основания хранятся отдельно. Пример, объяснение или дополнительная инструкция остаются в основном тексте, если помогают избежать конкретной ошибки.
7. Сжатие сохраняет контракт. Нельзя сокращать текст за счёт потери применимости, обязательного поведения, существенных границ или доступности ресурсов.
8. Все ссылки поддерживают переносимость, симлинки не использовать.

Для скиллов и правил:
Заменить обязательные четыре раздела Fails-when → What happened → How to fix → Why should be fixed на смысловой контракт:
Когда применяется → Что требуется → Как выглядит соблюдение. Это требования к содержанию. Названия разделов, их количество и порядок не обязательны. Одно предложение может быть достаточным и покрывать весь контракт, но сокращение не должно удалять обязательное поведение.

Для скиллов и правил:
С прежними пунктами поступать так:
Прежний пункт	Требование в новом стандарте
Fails-when	Нарушение должно быть определимо; отдельное описание нужно только при неоднозначности или возможном двояком толковании.
What happened	История сохраняется в заявке, уроке или отчёте; 
How to fix	Требуемое поведение или ограничение сохраняется непосредственно в инструкции
Why should be fixed	Краткое основание добавляется, если оно помогает правильно применять требование; подробное обоснование — отдельно

Для скиллов добавляется переносимый формат:
- Папка с SKILL.md: YAML frontmatter и Markdown-инструкции.
- Явные name и description.
- name: 1–64 символа; для общего профиля использовать a-z, цифры и дефисы, без крайних и последовательных дефисов; имя совпадает с папкой.
- description: 1–1024 символа, способность и точные условия применения; алгоритм действий, ограничения остаются в теле.
- Ресурсы создаются по необходимости; ссылки внутри комплекта переносимы.

Размещение скилла:
Материал	Канонический источник	Установочные копии
Общий скилл	harness/common/skills/	Полные одинаковые папки в [.agents/skills] и [.claude/skills]
Проектный скилл	harness/project/skills/	Полные одинаковые папки в [.agents/skills] и [.claude/skills]

Конкретный состав папки скилла:
.agents/skills/<prefix>-<name>/	и .claude/skills/<prefix>-<name>/	Папки скилла.	
<name>/SKILL.md	Обязательный файл: YAML-метаданные и Markdown-инструкции
references/	необязательная папка: дополнительные инструкции, справочники, описания форматов
scripts/	Необязательная папка: скрипты, которые агент запускает при выполнении задачи
assets/	Необязательная папка: шаблоны документов, изображения, файлы для создаваемого результата
agents/openai.yaml	Необязательный файл: отображаемое имя, описание для интерфейса, иконки, политика автоматического вызова, зависимости
Минимальный комплект — один SKILL.md в .agents/skills/<prefix>-<name>/	и копия в .claude/skills/<prefix>-<name>/. references/, scripts/ и assets/ — рекомендуемые названия, а не обязательные каталоги.
Названия папок помогают организовать файлы. Указания в SKILL.md определяют их применение.

Для правил добавляется контракт:
- Markdown с понятной областью применения и обязательным поведением.
- Постоянная загрузка оправдана требованием, которое нужно знать до выбора скилла.
- В текущем harness сохраняется размещение без paths - загрузка как always loaded rules, а не по открытию файла.
- Применимость должна быть понятна из тела потому, что: Claude Code читает у правил только поле paths, остальные поля frontmatter, включая description, игнорирует и передает модели только тело в виде инструкции.

Проектное правило	harness/project/rules/	Одна обычная копия в [.claude/rules]
