# Оценка без человеческих README

При оценке скилла, правила или инструкции через plugin-eval запускай установленный анализатор отдельным Node.js процессом через `harness/common/scripts/plugin_eval_without_human.mjs`.
Фильтр действует только в памяти этого процесса: исключает точное имя `README.human.md` на любой глубине до чтения и расчёта стоимости.
Прямое чтение такого файла, в том числе через симлинк, завершает запуск ошибкой до чтения тела.
Человеческие описания остаются на своих местах; исходники оцениваемого материала и установленного plugin-eval не меняются.

## Запуск из корня проекта

Нужны Node.js и установленный plugin-eval с JavaScript entrypoint.
В текущей установке команда plugin-eval указывает на такой entrypoint; launcher сам разрешает установочный симлинк.
Если команда другого окружения является shell-shim, найди JavaScript entrypoint установленного пакета и передай его первым аргументом; не привязывай переносимую процедуру к домашнему каталогу или cache автора.

```sh
plugin_eval_entry=$(command -v plugin-eval) || exit 1
node harness/common/scripts/plugin_eval_without_human.mjs "$plugin_eval_entry" analyze harness/common/skills/comm-create-lazy-claude-codex-skills --format markdown
```

Для маршрутизации замени `analyze` на `start`, для оценки объёма — на `explain-budget`; аргументы установленного CLI сохраняются.
Для скилла выбирай его собственную папку с SKILL.md; для плагина — корень настоящего пакета с manifest.
Для plain rule или инструкции выбирай ограниченную папку проверяемого комплекта: это generic-анализ, а не специализированная оценка скилла/плагина и не доказательство нативного поведения агента.
В установленном plugin-eval 0.1.2 произвольный одиночный Markdown-файл не проходит directory-based budget walk; не выдавай этот отказ за результат оценки.

Launcher работает без записи файлов через используемые анализатором promises API.
Сохраняй отчёт перенаправлением stdout в отдельный файл вне проверяемого комплекта; `--output`, `--brief-out`, benchmark/init-benchmark и создание конфигурации не входят в этот read-only запуск.
Внешние metric-pack процессы не наследуют фильтр и запрещены здесь; их проверка требует отдельной процедуры.

Проверка `.venv/bin/python -m pytest harness/common/testing/tests/test_plugin_eval_without_human.py` использует реальный установленный анализатор для скилла, плагина и plain rule, проверяет вложенные README, прямое чтение и симлинковый обход, неизменность входов и кода plugin-eval.
Статическая оценка токенов не является измеренным расходом сессии.
Это проверенный способ для текущих файловых API plugin-eval, а не ОС-изоляция или общий запрет доступа к файловой системе; после обновления анализатора повтори интеграционную проверку.
