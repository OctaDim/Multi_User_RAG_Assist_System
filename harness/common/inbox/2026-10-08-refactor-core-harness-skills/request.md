## Требуемый результат: семь задач вместо трёх широких процедур

Сохранить технические имена трёх существующих владельцев, сузив их назначение;
выделить четыре самостоятельных скилла. Целевой состав:

| Скилл | Запрос и результат |
|---|---|
| `comm-process-harness-inbox` | Создать, выполнить или возобновить заявку; полный состав, разрешённое выполнение, последовательность и актуальный статус |
| `comm-preserve-harness-knowledge` | Сохранить опыт/решение или разместить материал; reuse существующего владельца либо минимальный обоснованный новый материал |
| `comm-create-lazy-claude-codex-skills` | Создать/изменить инструкцию; компактный полный кандидат с применимостью, действиями и критерием соблюдения |
| `comm-validate-harness-instructions` | Проверить существующую инструкцию/кандидат; результаты, findings, обязательные проверки и фактические статусы |
| `comm-publish-harness-instructions` | Опубликовать подготовленную версию; разрешённый перенос после текущего gate, полные обычные native-копии и проверки интеграции |
| `comm-install-harness` | Установить/перенести пакет; рабочий выбранный режим с сохранением существующего project |
| `comm-diagnose-harness-entrypoints` | Диагностировать ошибку/предупреждение входов; причина и допустимое исправление без прямого редактирования защищённых настроек |

`comm-preserve-text-line-endings` и `comm-resolve-permission-blockers` сохранить
как самостоятельные существующие компетенции. Не менять их поведение; лишь
обновить необходимые ссылки при переносе владельцев. Не создавать отдельный
скилл только ради команд запуска тестового набора.

## Карта переноса ответственности

- Inbox: состав, разрешённые стадии, очередность, продолжение и закрытие остаются
  в inbox. Выбор формы знания из experience-routing переносится к сохранению знания.
- Авторство: content-contract и проектирование кандидата остаются у авторства;
  методика проверки и human-filter evaluation — у проверки; gate публикации,
  размещение skill/rule копий и проверка их полноты — у публикации.
- Установка: checks и применимые команды testing остаются у установки;
  entrypoints — у диагностики; размещение материалов и семантика дат — условные
  ветви сохранения знания. Миграционные требования сохранить у реально выполняющей
  их процедуры, не растворить между папками.
- Ранние ограничения сохраняются в rules, подробный алгоритм — у одного владельца.
  Применимые rules и указатели обновляются вместе с переносом, с прежней защитой
  разрешений, порядка чтения, common/project, human exclusion и статичных входов.
- Исторические рассказы, в частности описание удалённого «в этой задаче» hook,
  убрать из рабочих ресурсов, сохранив существенные основания и прежние свидетельства.

Описание каждого скилла должно различать запросы, а его тело вести к результату:
исходные данные → необходимые действия → критерий завершения. Ресурсы читаются
по точным условиям. Не оставлять прежние широкие скиллы дополнительными
маршрутизаторами поверх новых и не загружать всю цепочку на любой запрос.
Авторство использует проверку/публикацию только на соответствующей стадии;
публикация не пропускает обязательные проверки текущей версии.

## Цели размера, качества и загрузки

Применить требования первой заявки: SKILL.md обычно до 200 слов, сумма ресурсов
стремится к ≤1000 статически оценённых токенов, превышение текущего deferred
порога анализатора 1200 устранено; целевая evaluate-skill категория A без открытых
ошибок. Фактические пороги и версию инструмента сохранять в отчёте.

Для каждого нового/изменённого скилла использовать `plugin-eval:evaluate-skill`
(start → analyze с human-фильтром). Разбирать findings, исправлять причины,
повторять оценку и сравнивать версии. Сравнить и суммарные metadata/startup,
и фактическое чтение на одинаковых задачах, и полный комплект зависимостей.
Рост метаданных объяснить; не объявлять экономию по одним размерам папок.
Не повышать thresholds, не скрывать обязательный текст вне оценки и не добавлять
искусственный plugin manifest/coverage ради баллов. Оценка не доказывает native behavior.

Использовать существующую
[заявку подробного budget-отчёта](../2026-10-07-plugin-eval-budget-details/request.md)
и её результаты по применимости; не создавать конкурирующий анализатор или
принудительную зависимость от ещё не опубликованного скилла этой заявки.

## Полные исходные приложения

source-skills содержит обычные полные папки всех трёх исходных скиллов со всеми
ресурсами и человеческими пояснениями. source-rules содержит полные исходные
файлы применимых правил, указатели которых затрагивает разделение. Полные sets
и hashes сохранены в манифесте; human bodies исключены из агентского контекста.

Это исходный комплект для сравнения и подготовки кандидата при обработке,
не семь уже реализованных скиллов. После актуального RED подготовить здесь
полные папки финальных кандидатов и полный набор изменяемых правил, не только
фрагменты. Отчёты рядом оценивают исходные приложения, а не будущую реализацию.

## Приёмка при последующей обработке

1. Для каждого требования есть карта исходный пункт → новый владелец → проверка;
   сопоставление завершено до удаления/замены освобождённых ресурсов.
2. Новая самостоятельная задача выбирает свой скилл; авторство сохраняет требования
   первой заявки при создании, дополнении и редактировании. Посторонняя задача
   не загружает тела/ресурсы этих скиллов.
3. Сопоставимые сценарии: создать/возобновить заявку; сохранить покрытый опыт;
   сохранить новый опыт; создать/изменить инструкцию; проверить её без публикации;
   опубликовать с недостающей проверкой/разрешением; установить harness;
   диагностировать повреждённый вход; посторонний запрос.
4. Сохранены действующие границы разрешений, отдельного подтверждения прямого
   обхода и последовательности заявок; неполные данные не дают ложного успеха.
5. Оба режима установки: common-only с нейтральным project, combined с побайтным
   сохранением существующего project; project-only остаётся отрицательным контролем.
6. RED исходной версии → компактный кандидат → GREEN. Проверить явный вызов
   собственных ресурсов, неявный выбор и незагрузку посторонних отдельно у каждого
   агента по обязательной текущей процедуре. Повторить после последней правки.
7. evaluate-skill каждого нового/изменённого скилла, применимые внешние проверки,
   проверка ссылок, ресурсов и существующие содержательные регрессии выполнены.
   Сравнение баллов, статических бюджетов и реального чтения содержит ограничения.
8. Старые рабочие указатели обновлены; защищённые AGENTS.md/CLAUDE.md и согласованный
   каркас не переписаны; исторические результаты не выданы за текущие успехи.
9. После разрешённого gate канонические папки в common/skills и полные обычные
   одноимённые копии в .agents/skills и .claude/skills равны по sets/bytes и видимы Git.
   Для правил проверить весь установленный canonical/shared набор, не только изменения.
10. Статусы соответствуют реально выполненным проверкам. Отчёт и полезные основания
    сохранены вне inbox; удаление заявки не ломает рабочие процедуры.
