## RED → GREEN

Команда из корня проекта:

```sh
python3 -B -m unittest discover -s harness/common/checks -p 'test_*.py'
```

До изменения производственного кода добавлены три регрессионных теста:

1. Все обязательные ссылки и инструкция чтения правил внутри блока с более
   длинным закрытием не засчитываются; реальные строки добавляются после блока,
   пользовательский префикс сохраняется, повторный запуск не меняет файл.
2. Незакрытый блок в AGENTS.md либо CLAUDE.md с тильдами либо обратными кавычками
   даёт exit 2; оба файла побайтово сохраняются, .claude не создаётся.
3. Строка ~~~example внутри блока не закрывает его; добавление сгенерированной
   инструкции внутри кода вызывает предупреждение об изменении относительно Git.

RED: exit 1, 26 тестов, шесть провалов подслучаев новых регрессий.
Для тильд длинное закрытие не восстановило подключения; четыре незакрытых блока
дали ошибочный exit 0; изменение внутри примера не вызвало предупреждение.
Длинное закрытие обратными кавычками уже обходилось прежним inline-code regex;
этот контроль сохранён. Полный [вывод RED](red.txt).

## Независимый review и повторная проверка

По superpowers:requesting-code-review выполнен отдельный read-only review.
Обнаружена регрессия: незакрытый блок в историческом HEAD вызывал ошибку при
сравнении, даже если текущий AGENTS.md уже исправлен. Это превращало необязательное
предупреждение Git в блокировку восстановления исправного текущего входа.

До дополнительной правки добавлен четвёртый тест: незакрытый AGENTS.md сохранён
в HEAD временного Git-проекта, в рабочем файле блок закрыт. Проверка должна
предупредить об изменении и восстановить ссылки, сохраняя пользовательский текст.
RED: 27 тестов, один провал — exit 2 вместо 0. [Вывод](review-red.txt).

Исправление: без дублирования разбора without_startup_links допускает незакрытый
исторический блок до EOF; instruction_text сохраняет строгий отказ для текущего
входа до записи. GREEN итоговой версии: exit 0, 27/27. [Вывод](final-green.txt).
Повторный независимый review подтвердил исправление, 27/27, равенство копий и
отсутствие блокирующих замечаний в согласованной области. Отдельно проверены оба
символа, отступы 0/1/3 пробела, длинные закрытия, пробел/табуляция после закрытия,
ложные закрытия коротким/другим разделителем или с текстовым суффиксом.

Финальная проверка входа в текущем проекте: exit 0, входы не изменены.
git diff --check: exit 0.

## Автономность

В каждый временный проект скопированы только выбранные полные папки harness.
Проверка запускалась собственным установленным скриптом через Python -I -B,
с PATH без Git: common-only, project-only, common+project.

Во всех трёх режимах итоговой версии: восстановление вне закрытого блока,
неизменность повторного запуска, отказ без записи для незакрытых блоков в каждом
текущем входе и успешное восстановление при повреждённом историческом HEAD — PASS.
Git-сценарий выполнялся с локальным временным репозиторием, остальные — без Git.
Финальные результаты и равные хеши:
[installation-modes-final.txt](installation-modes-final.txt).
Первый прогон до замечания review сохранён отдельно:
[installation-modes.txt](installation-modes.txt); его хеш относится к промежуточной версии.
Изоляция временными каталогами и параметрами запуска, не запрет ОС на чтение
исходного проекта. Скрипт использует только стандартную библиотеку и файлы
установленного временного проекта; запуск другого агента этим не проверяется.
