# Единый разбор fenced-блоков при проверке входов

Дата создания: 2026-10-05.

## Контекст

- Когда возникла потребность: при полном аудите GLOBAL_HARNESS_ENVIRONMENT 2026-10-05.
- Обстоятельства: входная проверка и все 23 прежних теста проходили, но временные
  AGENTS.md воспроизвели ложный успех на примерах кода и пропуск предупреждения Git.
- Причина: instruction_text использует регулярное выражение с точным повторением
  разделителя; without_startup_links имеет отдельный построчный разбор, принимающий
  строку с суффиксом за закрытие блока.
- Что решит выполнение: ссылки и инструкции внутри fenced-кода перестанут
  засчитываться как установленное подключение и исключаться из сравнения с Git.
- Требуемый результат: единый построчный разбор для обеих проверок, регрессионные
  тесты, одинаковые автономные common/project копии проверки входов.

## Согласование и решение

Пользователю предложены три варианта исправления. Выбран ответом «2» вариант
единого построчного разбора на основе существующего кода. Это подтверждение
создания и выполнения первой заявки, предложенной после аудита.
После создания заявки пользователь прямо подтвердил: «и сразу выполни эту заявку
из inbox».

Закрытие: тот же символ, длина не меньше открывающего разделителя, после него
только пробелы/табуляции. Незакрытый блок в текущем входе: диагностическая ошибка
до записи, без автоматического закрытия или добавления ссылок внутрь блока.
При сравнении с Git незакрытый исторический блок считается кодом до конца текста
и не блокирует работу с исправным текущим входом.

Область: код проверки входов, его проектная копия, регрессионные тесты и описание
поведения. Правила и скиллы не изменяются. Остальные пункты аудита, включая CRLF,
не входят в эту заявку; последующие заявки требуют отдельного решения пользователя.
