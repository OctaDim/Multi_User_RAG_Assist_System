# Обязательные границы создания и публикации

- Каждая новая заявка: отдельная `inbox/YYYY-MM-DD-суть-заявки/`. Контекст обязателен: когда возникла потребность, обстоятельства, причина, что решит выполнение, требуемый результат.
- Без явного канонического указания сохранять в заявке контекст, результат и **полную папку скилла со всеми ресурсами либо полный файл правила**; по умолчанию не публиковать. Прямое каноническое создание требует явного указания и подтверждения пользователя; один запрос может содержать оба.
- `skill-creator` и внешние проверки обязательны во всех проектах. Нет инструмента — предупредить, предложить установку в окружение разработчика, статус «непроверен». Установка сама по себе не означает проверку.
- Правила: общие переносимые — harness/common/rules/comm-<name>.md; проектные переносимые — harness/project/rules/proj-<name>.md. После gate при переносе из inbox автоматически сохранить источник и обычную копию в .claude/rules/<то же имя>.md; схема octadim/ отменена.
- Для скиллов и правил перед переносом в harness и нативные каталоги проверять повторно; статусы Codex и Claude фиксировать отдельно. Полная проверка — успех у обоих и общих проверок для текущей версии. Неуспех, недоступность или пропуск — «не проверено»; правка отменяет прежние статусы. До разрешённого переноса кандидат остаётся в inbox; копирование статус не меняет. Недоступная/красная проверка требует явного разрешения на публикацию **непроверенной текущей версии**. Обычный запрос о переносе не является разрешением пропустить проверку; исключение не меняет статус на «проверен».
- При создании скилла/правила: сначала сохраняемый контракт и RED без новых инструкций, затем компактная версия и проверка итогового поведения. После правок повторить проверки; подробный порядок — `harness/common/docs/compact-authoring.md`. Уже компактный материал искусственно не ужимать.
- Применимые канонические comm-/proj- требования приоритетнее индивидуальных; skip/override запрещены. Конфликт common/project — согласовать и ждать ответа.

При создании или переносе скилла или правила открыть lazy-процедуру из корня проекта: `harness/common/skills/comm-create-lazy-claude-codex-skills/SKILL.md`; контракт размещения — `harness/common/docs/skill-rule-ownership-contract.md`. Подробности на старте не читать.
