# Папки заранее и человеческие пояснения: проверка правила

Дата: 2026-10-04. Объект: [правило](../rules/comm-human-folder-guides.md).

## Требование пользователя

Согласованная структура создаётся заранее, даже без рабочих материалов. Каждая папка harness получает человеческое пояснение с понятным примером. Агент не должен читать тело пояснения или расходовать на него контекст. Эта директива отменяет предложение агента не создавать пустые категории.

На момент проверки нового правила одинаковые категории в common/project ещё не были выбраны; пояснения были созданы для трёх существовавших папок harness. Позже 2026-10-04 пользователь выбрал одинаковые категории и добавил handoff/. Проверка расширенной структуры записывается отдельно в [mirrored-layout-evidence.md](mirrored-layout-evidence.md); исходный эксперимент этим решением не расширяется.

## Наблюдения

Один и тот же временный пример передан двум отдельным агентам с чистым контекстом. Задача: найти место и доказательство для опыта исправления повторного HTTP-запроса; предложить testing/inbox без рабочих материалов.

- Без нового правила агент сообщил о чтении INDEX.md, lessons/README.human.md, lessons/repeat-request.md и правила независимости; предложил категории без пояснений.
- С правилом агент сообщил о чтении индекса, рабочего урока и правил; README.human.md отсутствует в списке прочитанного. Для новых категорий предусмотрел обязательные пояснения, включая иллюстративный пример.
- Это одна пара сценариев и списки файлов, сообщённые участниками; она не доказывает надёжность всех будущих сессий или техническую невозможность чтения. Полного независимого журнала файловых обращений не собрано.
- Реальный вызов rg с исключением README.human.md в том же примере вернул рабочий урок без человеческого пояснения.

## Проверка сохранённых файлов

Программная проверка прошла: пояснения есть в 3 из 3 существующих папок harness; каждое содержит заголовок и пример. Обе ссылки INDEX.md разрешаются внутри common и не ведут к README.human.md. Реальный rg --files с исключением человеческих пояснений сохранил 3 агентских файла: индекс и два правила. Тела пояснений в выводе проверки отсутствуют. Это проверка существующих папок, не всей ещё несогласованной структуры. git diff --check прошёл; рабочее дерево исходного проекта осталось чистым.

## Статическая оценка

Выполнены plugin-eval start и analyze для временного кандидата с правилом и индексом: generic directory, 0 fail, 0 warn, оценка 485 токенов, измеренного usage нет. Generic-классификация не проверяет загрузчики Codex/Claude и не доказывает нулевую стоимость.

Применены принципы skill-creator и writing-skills. Форматы SKILL.md и plugin.json здесь не создавались; специализированные evaluate-skill/evaluate-plugin не объявляются пройденными. plugin-management: доступного локального инструмента достаточно, новые подключения не создавались.

## Ограничения

Проверка файлов и индекса выполняется программно с выводом только результатов и путей; тела человеческих пояснений в контекст не выводятся. Подключение правила к обязательному стартовому контексту и проверки всех реальных загрузчиков/режимов остаются частью будущего этапа. Запрет произвольного чтения файлов на уровне инструментов или ОС не реализован. Исходный проект не изменялся.

## Уточнение после переноса

2026-10-05: свидетельство перенесено внутрь common. Название категории сейчас `handoffs/`; упоминания `handoff/`, количества ссылок и размеров выше описывают прежний эксперимент. Новые файлы не расширяют его доказательства. Текущие требования: [приёмка](acceptance.md).
