# Validation and publication

## Request packet

Each request: own inbox/YYYY-MM-DD-purpose/; creation date, meaningful name/suffix.
Context: when need arose, circumstances, reason, problem solved, required result/acceptance.
Mark unknowns and ask; never invent dates/causes.

Without canonical instruction save request.md, validation.md and full skill/name/resources
or complete rule file; links/descriptions are insufficient. Save request authorizes capture;
otherwise ask. New folders need README.human.md with explained example; exclude its body
from search, context, imports and evaluation.

## Required tools

Read named skills/resolve helpers in the current catalog; no author-home/cache dependencies.
Invoke applicable tools and record results.

| Stage | Skill and required result |
|---|---|
| Process | superpowers:using-superpowers before authoring; target harness/scope |
| Codex/OpenAI requirements | openai-docs; search and fetch current official guidance |
| Skill design | skill-creator and quick_validate.py on the final folder |
| Behavior | superpowers:writing-skills RED–GREEN–REFACTOR on the compact contract |
| Evaluation route | plugin-eval:plugin-eval |
| Skill report | plugin-eval:evaluate-skill; run analyze, review findings and recommendations |
| Actual plugin manifest | plugin-eval:evaluate-plugin; otherwise N/A |
| Skill corrections | plugin-eval:improve-skill; read generated brief; required/recommended fixes; skill-creator; re-evaluate/compare |

Use plugin-management:plugin-management for integration/installation. Missing tools:
warn, offer/authorize installation, then check. Failed/unperformed checks leave unverified
inbox; installation is not validation. Static tokens are not measured usage.
Benchmark files/configuration/dependency changes require write authorization.

## Standalone rules

Use skill-creator's scope/non-duplication principles; preserve project format
and Fails-when → What happened → How to fix → Why should be fixed. Justify always-loaded
placement by a failure before skill selection. Check conflicts/references, compactness and both agents' behavior. Plain rules: generic analysis is not evaluate-skill/plugin or native proof; no skill validator.
Plugin rules require evaluate-plugin. Recheck corrected rules; improve-skill corrects skills.

## Gate and report

Process inbox separately on request; select common/project, necessity, name, compactness.
Repeat final format/resources, helper behavior, RED–GREEN–REFACTOR/evaluation; edits invalidate
status. Test native listing, explicit own-resource use and implicit selection separately.

validation.md: date/version/files, commands/tools, agent versions/scope, contract/compactness method,
pass/fail/not-run/N/A reasons, findings, missing tools, next steps; separate Codex/Claude
statuses and three installation modes. Verified requires all current mandatory checks
and no unresolved correctness/discovery/behavior findings. File equality is not native proof.

Missing/failed checks: retain inbox; obtain explicit permission for this unverified version
at named source/native paths. Transfer request, old success/deadline is no waiver.
Exceptions preserve status/constraints. After gate check source/full copies: file sets,
regular files, equality, Git and native behavior. New failures need current gate/exception
for further publication. Current report: package checks; earlier evidence: inbox.
