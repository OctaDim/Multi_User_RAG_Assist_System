# Расширение процесса создания скиллов и правил

Дата заявки и возникновения потребности: 2026-10-05.
Обстоятельства: пользователь попросил добавить семь названных скиллов в окружение harness. Целевое окружение — WSL Ubuntu-24.04, проект GLOBAL_HARNESS_ENVIRONMENT. После ошибочной правки Windows AGENTS.md пользователь уточнил область действия и поручил откатить её и выполнить задачу правильно; добавленный Windows-раздел удалён с проверкой.
Причина: существующая процедура авторинга не закрепляет using-superpowers, OpenAI Docs и improve-skill; её description не включает самостоятельные правила.
Что решит выполнение: явный выбор и применение инструментов на соответствующих этапах создания, оценки и улучшения скиллов и правил.
Требуемый результат: компактное обновление существующей lazy-процедуры с полной папкой ресурсов; применение всех семи скиллов по назначению, сохранение требований размещения, RED–GREEN–REFACTOR и независимых статусов Codex/Claude.
Приёмка: формат и ссылки валидны; сценарии охватывают скилл, самостоятельное правило, плагин, исправление findings и недоступную проверку. Нативная приёмка обязательна для обоих агентов в трёх режимах установки.

## Сохраняемый контракт
- using-superpowers определяет процесс и применимые скиллы до работы.
- openai-docs проверяет актуальные Codex/OpenAI требования; skill-creator задаёт структуру и валидацию скилла.
- plugin-eval выбирает оценку; evaluate-skill оценивает скилл; evaluate-plugin применяется к реальному plugin manifest.
- improve-skill связывает выявленные недостатки с исправлением и повторной оценкой.
- Самостоятельное правило проверяется как правило; его Markdown-анализ не считается оценкой скилла/плагина или нативной загрузкой.
- Для правил сохраняется Fails-when → What happened → How to fix → Why should be fixed.
- Пути скиллов разрешаются в текущем окружении; Windows-пути и версии кэша не становятся зависимостями пакета.
- Неизменны запрет чтения README.human.md, защищённые входы, приоритет canonical требований, полные обычные копии и gate публикации.

## Исходная проверка RED
Независимый проход по текущим инструкциям: сценарий создания Codex-скилла с плохим trigger и broken reference не требует отдельного documentation workflow или improve-skill; сценарий самостоятельного always-loaded правила не выбирает существующий скилл. Сценарий недоступного Claude корректно оставляет материал непроверенным. Это проверка решений по инструкциям, не нативная приёмка.

## Правило запуска внешних WSL-инструментов
**Fails-when:** Python через прямой wsl.exe не находит инструмент, доступный в login shell.
**What happened:** subprocess не нашёл plugin-eval из ~/.local/bin при первом запуске исходной оценки; кандидат ещё не изменялся.
**How to fix:** выполнять Python и внешние команды в bash -lc внутри Ubuntu-24.04 с прежним окружением разработчика; многострочный Python передавать через stdin, а не интерполировать shell-переменные.
**Why should be fixed:** различающийся PATH не должен ошибочно считаться отсутствием установленного инструмента или приводить к повторной установке.
Это узкое правило для данного способа запуска; изменение глобальных настроек не требуется.

## Правило передачи многострочного кода
**Fails-when:** escape при передаче Python через несколько уровней литералов становится переносом внутри обычной строки.
**What happened:** вспомогательная правка завершилась SyntaxError до записи.
**How to fix:** использовать тройные Python-строки и stdin.
**Why should be fixed:** предотвратить ошибки экранирования без правок окружения.

## Исправление объёма
Plugin Eval выявил превышение порога deferred cost. Удалены дублирующие формулировки; область, обязательные действия, отчёт и gate сохранены. Повторная оценка выполняется на компактном комплекте.

## Правило проверки ветвей сценария
**Fails-when:** scorer требует условие именования скилла в сценарии standalone rule.
**What happened:** два корректных rule-ответа получили false fail из-за поиска 64.
**How to fix:** оценивать только ограничения выбранного типа; вручную читать flagged ответы и сохранять исходные flags.
**Why should be fixed:** исправление критериев должно устранять ложное срабатывание без подгонки инструкций или результатов агента.
