Использую `comm-preserve-text-line-endings` и его `references/regressions.md`.

В текущем common checker исправление уже есть: входы читаются и записываются через bytes, а окончания вставок выбираются отдельно для каждого файла. `read_text()/write_text()` может заменить CRLF вне вставок, поэтому равенство смысла и срок не оправдывают такую замену.

Git-репозитория здесь нет; сравнение с HEAD не проверено. Регрессионные тесты создают временные файлы, поэтому в вашем режиме «ничего не создавай» ограничусь чтением кода и тестов.

Исправление уже реализовано в `harness/common/checks/ensure_entrypoint_links.py`. Заменять его на `read_text()/write_text()` нельзя: нормализация CRLF меняет байты вне разрешённых вставок. Срок этого ограничения не отменяет.

Правильный ремонт через common checker:

- Читать `read_bytes().decode('utf-8')`, записывать `write_bytes(text.encode('utf-8'))`; при ошибке UTF-8 прекращать ремонт.
- Сохранять исходные байты, включая смешанные окончания строк. Для вставок выбирать первый LF/CRLF каждого файла отдельно, при отсутствии — LF.
- В AGENTS добавлять только недостающие ссылки и указание чтения правил; в CLAUDE — недостающий `@AGENTS.md` перед исходным содержимым. Лишний текст сохранять и выдавать предупреждение.
- Повторный запуск должен сохранять bytes, не дублировать подключения и не сообщать о повреждении.
- На временных fixtures проверять исходный префикс AGENTS, исходный суффикс CLAUDE, окончания вставок и повтор. Для Git — отсутствие ложного предупреждения относительно HEAD после ремонта CRLF; одного `git diff` недостаточно.
