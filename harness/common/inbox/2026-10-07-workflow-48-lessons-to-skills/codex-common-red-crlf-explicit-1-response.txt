Обычные `read_text/write_text` применять нельзя: универсальное чтение нормализует CRLF в LF. Одинаковый смысл не гарантирует сохранения байтов.

В проверенном `ensure_entrypoint_links.py` исправление уже реализовано:

- Входы читаются через `read_bytes().decode('utf-8')`, записываются через `write_bytes()`.
- Недостающие ссылки дописываются с первым найденным окончанием строки; при отсутствии используется LF.
- Импорт `@AGENTS.md` вставляется перед существующим содержимым с выбранным окончанием строки.
- Постороннее содержимое сохраняется.

Для CRLF-регрессии нужны проверки сохранности исходных байтов, CRLF во вставках и побайтовой неизменности после второго запуска. Здесь входы имеют LF; CRLF-сценарий и повторный запуск не проверены. Прямые правки входов не нужны.

В Git следует проверить `git status --short`, `git diff --check` и `git diff -- AGENTS.md CLAUDE.md`; побайтовая проверка нужна отдельно, поскольку Git может нормализовать окончания строк. Здесь `git status` завершился ошибкой: каталог не является репозиторием.
