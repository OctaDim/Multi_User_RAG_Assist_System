Применю `comm-preserve-text-line-endings` и его `references/regressions.md`. Первой командой выполню обязательную стартовую проверку; работа останется read-only.

`read_text()/write_text()` здесь неприемлемы: одинаковый смысл не гарантирует сохранение CRLF и исходных байтов. Срок этого требования не отменяет.

Исправление уже есть в `harness/common/checks/ensure_entrypoint_links.py`:

- Читать через `read_bytes().decode('utf-8')`, записывать через `write_bytes(text.encode('utf-8'))`; ошибки UTF-8 не заменять символами.
- Сохранять исходные байты, включая смешанные окончания строк. Для вставок брать первый LF/CRLF **каждого файла отдельно**, при отсутствии — LF.
- В `AGENTS.md` добавлять только недостающие стартовые ссылки и инструкцию чтения правил. В `CLAUDE.md` добавлять недостающий `@AGENTS.md`, сохраняя существующий текст; корректный CRLF-импорт распознавать без ремонта.
- На временных fixtures проверять точные байты вставок и неизменность исходного содержимого. Второй запуск должен сохранять байты без дубликатов и сообщения о восстановлении.
- При наличии Git проверять сравнение с `HEAD`, отсутствие ложного предупреждения после CRLF-ремонта и `git diff --check`. Сам diff не доказывает равенство байтов.

Обязательный старт завершился успешно, без сообщения о восстановлении. Прямых правок входов, создания материалов и публикации не выполнял. Регрессионные тесты не запускал: они создают временные файлы, что противоречит вашему ограничению. Git-репозитория здесь нет; сравнение с историей и проверка diff **не проверены**.
