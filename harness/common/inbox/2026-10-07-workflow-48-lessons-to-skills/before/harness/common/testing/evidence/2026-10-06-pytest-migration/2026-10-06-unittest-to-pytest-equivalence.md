# Эквивалентность миграции на pytest

Дата создания: 2026-10-06. Область: все исходные тесты репозитория,
включая скрытые каталоги и исполняемые копии inbox; установленные библиотеки `.venv` не являются
исходным кодом репозитория. Человеческие README исключены из чтения и поиска.

## Результат и запуск

17 файлов, семь уникальных исходных редакций, 122 метода полностью переведены
в обычные pytest-классы без TestCase: `assert`, `pytest.raises`, autouse/tmp_path,
`monkeypatch.context()` и параметризация. Новый основной набор — 57 случаев;
все шесть редакций — 182 случая. Все прошли на Python 3.12.15 и 3.9.25.
Продукционная логика checker, launcher и всех редакций check_rule_copies
сохранена. Новые тестовые пропуски или xfail не введены.

Локальная `.venv` создана через uv и исключена из Git. Зависимости pytest 8.4.2
и coverage 7.10.7 совместимы с Python 3.9; условные транзитивные зависимости
зафиксированы universal lock. [Команды](../../../docs/2026-10-06-run-tests.md) работают из корня.
Корневой pytest.ini собирает только основной набор; run_tests.py отдельно
запускает все редакции, включая 12 файлов inbox.

| Редакция | Исходные методы | pytest-случаи |
|---|---:|---:|
| Установленный common | 39 | 57 |
| rules-entrypoint/candidate | 2 | 4 |
| workflow-43/merged | 2 | 4 |
| workflow-43/publication-before | 2 | 4 |
| inbox-authorization-interpretation/candidate | 39 | 57 |
| two-installation-modes/candidate | 38 | 56 |
| Всего | 122 | 182 |

Увеличение — раскрытие subTest в отдельные параметры. Последовательность
повреждения, исправления и финального восстановления копий сохранена внутри
каждого режима. Общая финальная проверка отсутствия common теперь повторяется
после каждого параметра; ни одно утверждение не удалено. Интеграционный тест
launcher сохраняет последовательный проход skill/rule/plugin, два вида чтения
и запрет записи, а также итоговую неизменность установленного анализатора.

## Карта и исходные свидетельства

[unittest-originals.json](2026-10-06-unittest-originals.json) содержит все оригинальные
исходники как данные, SHA-256 и Git revision. Это не исполняемые unittest-копии;
для воспроизведения baseline их можно восстановить только во временной установке.
В [карте](2026-10-06-pytest-equivalence-map.json) у каждого исходного метода сохранены
исходные утверждения, subTest, значения параметров, эквивалентные выражения
и все фактические pytest node IDs. Программная сверка AST подтвердила сохранение
каждого assert и каждой проверки класса/сообщения исключения, включая helper git.
Наборы collected node IDs полностью совпали с картой.

Исходные исторические отчёты, команды и manifests inbox не переписывались.
[Текущие manifests](2026-10-06-pytest-migrated-manifests.json) отдельно фиксируют все
мигрированные файлы и ресурсы каждой кандидатной редакции; прежние hashes
не объявляются hashes новой версии. Предшествующие результаты скиллов/правил
не повышаются из-за миграции тестов.

## Покрытие и чувствительность

[Baseline](2026-10-06-pytest-before.json) и [после миграции](2026-10-06-pytest-after.json) измерены
на одном Python 3.12.15, coverage 7.10.7 и одинаковых ресурсах. Покрытие дочерних
Python-процессов включено через patch=subprocess; Node.js — штатный V8 coverage.
Из Python-результатов сравнивались исполняемые checker и helper check_rule_copies,
а не изменившиеся строки тестов. Каждый существенный assert дополнительно
проверен картой. V8 сравнивает точные диапазоны блоков одного launcher.

[Сверка](2026-10-06-pytest-coverage-comparison.json): для всех шести редакций точно равны
наборы покрытых/непокрытых строк и ветвей Python и диапазонов блоков V8.
Стандартный summary coverage.py для основного checker: 153/160 строк
и 74/80 ветвей. Сырые trace-наборы содержат 154 выполненные записи строк
и семь невыполненных; у helper копий — 24 и одну соответственно, а также
17 выполненных и одну невыполненную ветвь. Эти trace-записи не выдаются
за стандартный процент покрытия. Проценты не заменяют совпадение наборов.

[Пять негативных контролей](2026-10-06-pytest-mutation-controls.json) выполнены только
во временных копиях: нормализация CRLF в LF, удаление уведомления до записи,
допуск симлинка входа, допуск лишней копии правила, отключение human-фильтра.
Для каждого дефект обнаружили и прежний, и новый соответствующие тесты:
10/10 запусков завершились ожидаемым падением. Продукционные файлы не менялись.

## Переносимость и независимая проверка

[Чистые установки](2026-10-06-pytest-portability.json) используют отдельные окружения uv
из lock; исходный проект и глобальные инструкции скрыты bwrap. Реальный
установленный plugin-eval скопирован в изолированный toolchain без human README.
Common-only: 55 PASS и два ожидаемых SKIP отсутствующего legacy shim;
common+project: 57 PASS. Условия и причина пропуска прежние: у нейтрального
project shim не создаётся; параметризация отдельно показывает два случая.
Project-only отказ, отсутствие записей при ошибке и идемпотентность входят в
обязательные успешные тесты. Старт выполнялся до установки pytest.
[Python 3.9](2026-10-06-pytest-python39.json): все 182 случая прошли с собственным окружением
uv и условными зависимостями из того же lock.

Независимый Codex reviewer проверил все 17 файлов, исходные snapshots,
карту, coverage, негативные контроли, runner/config, lock, действующие документы
и команды уроков и переносимость. Замечаний к реализации нет; два замечания
к отчёту исправлены: семь уникальных исходников и отдельные обозначения
стандартного summary coverage и сырых trace-записей. Финальные manifests
проверены: все 244 hashes совпали.

Codex — проверено в указанной области. Claude — непроверенный, не запускался.
Итог — непроверенный. Полная нативная приёмка скиллов/правил этим отчётом
не заявляется: их инструкции не изменялись. Прямые входы AGENTS.md/CLAUDE.md
не редактировались. Полный поиск исполняемого кода не находит unittest API;
исторические команды и JSON-данные исходников сохранены.
