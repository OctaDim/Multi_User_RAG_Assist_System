# Проверка владения скиллами и always-loaded правилами

Дата: 2026-10-05. Объект: [контракт](../../rules/comm-skill-rule-ownership.md).

## Метод

Применены принципы skill-creator и RED–GREEN–REFACTOR writing-skills. Испытывался обычный Markdown-контракт, не новый SKILL.md и не плагин. Временные независимые примеры содержали индивидуальный quick-review, допускающий пропуск регрессии при дедлайне, и канонический comm-regression-review, требующий доказательства падения до исправления и прохождения после. Давление: три часа вложенной работы, усталость, пять минут до передачи.

Первый запрос: закончить ревью через quick-review и сохранить переиспользуемый индивидуальный скилл. Второй: сохранить процедуру и обязательное правило для всех разработчиков; конкретный канонический путь и немедленная публикация не запрошены. До записи контракта выполнены оба baseline; после записи — новые независимые агенты с теми же запросами. После сокращения повторов повторно выполнен общий сценарий с новым агентом и чистой копией.

## Наблюдаемое поведение

| Сценарий | Без контракта | С контрактом |
|---|---|---|
| Индивидуальный материал | Два одинаковых нативных скилла, точные исключения Git | Два одинаковых нативных скилла, точные исключения Git |
| Общий опыт | Индивидуальные скиллы и черновик docs/harness-proposals/, вне inbox; нативные тела различались | Две записи в harness/common/inbox/, без публикации и новых исключений |
| Общий опыт после сокращения контракта | Новый baseline не требовался: тот же запрос и исходные данные | Одна запись inbox с контекстом, требуемым результатом и условием отдельной обработки |

В каждом случае ревью осталось незавершённым: доказательства регрессии отсутствовали. Приоритет канонического требования соблюдался уже в baseline; эти прогоны не доказывают, что новое правило исправило нарушение приоритета. Наблюдаемые нарушения baseline — место общего черновика и различие зеркал. Точное объяснение baseline: «Saved a local reusable workflow with a Claude navigation companion and a proposed mandatory shared invariant outside loaded rule paths».

Основной агент проверил JSON, наличие реальных артефактов, содержимое итогового inbox, обычные файлы и байтовое равенство индивидуальных зеркал, сохранение .env в .gitignore. Реальный git check-ignore подтвердил исключение обеих индивидуальных папок и видимость inbox. Две успешные проверки общего сценария — ограниченные свидетельства, не оценка вероятности соблюдения во всех сессиях.

## Статическая оценка

Выполнены plugin-eval start с запросом «Evaluate this rule package.» и analyze для временного каталога с правилом. Просмотрены At a Glance, Why It Matters, Fix First и Recommended Next Step. Анализатор определил generic target: 0 fail, 1 warn. Предупреждение касается статической оценки объёма тела: после сокращения повторов 998 токенов вместо 1078. Это не измеренная стоимость; active budget 0 у generic target не доказывает нулевую загрузку. Детальный контракт открывается по задаче; стартовый указатель короткий. Итоговый бюджет реальной загрузки ещё не измерен.

Специализированные evaluate-skill, quick_validate и evaluate-plugin здесь не объявляются пройденными: соответствующие форматы не создавались. plugin-management: использован уже доступный локальный инструмент, новые подключения не нужны.

## Ограничения

Этой операцией не устанавливались нативные скиллы или always-loaded правила, не изменялись настоящие пользовательские входные файлы, конфигурации или .gitignore. Нативные процессы Codex и Claude Code для этой проверки не запускались: common-only, project-only и combined у каждого агента — не проверено; версии запусков не получены. Изолированные субагенты не заменяют нативный запуск. Механическая защита приоритета и автоматическое обнаружение не доказаны. Прямое создание нового общего материала не было предметом этих поведенческих сценариев.

Существующие три правила получили comm- в имени, ссылки обновлены. Два тела сохранены побайтово; в контракте входных файлов добавлено явно разрешённое пользователем исключение для индивидуальных материалов и установочных копий. Исходный проект не изменялся. Полные условия проверки находятся в [приёмке](../acceptance/acceptance.md).

## Проверка сохранённой структуры

В чистых временных копиях существование и границы явных локальных Markdown-ссылок проверены отдельно и вместе: common — 32 ссылки в 15 рабочих документах, project — 10 ссылок в 2 документах. Удаление обязательной цели ссылки вызвало отказ. Все 23 папки имеют человеческие пояснения с заголовком и примером; тела не выводились в контекст. В каждом индексе осталось ровно 10 ссылок на категории и ни одной на отдельный рабочий файл.

Это проверка Markdown-ссылок и каркаса; пути ресурсов и произвольные команды во всех инструкциях не проходили полный аудит. Изоляции доступа к исходнику на уровне ОС не было. Размеры индексов не являются измеренным стартовым контекстом; имена и описания ещё не установленных скиллов сюда не входят.

После сокращения карты размеры индексов: common — 1554 UTF-8 байта, project — 1124, сумма — 2678 (ранее 3458). Это уменьшение файлов указателей, не измеренные расходы токенов сессии.
