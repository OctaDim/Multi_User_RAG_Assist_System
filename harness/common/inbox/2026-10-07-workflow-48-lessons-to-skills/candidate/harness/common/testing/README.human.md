# testing/ — пояснение для человека

TDD, регрессии и выбор тестов. Тестовая дисциплина, защита существующих тестов и условия выбора diff или полного набора.

Универсальные материалы, применимые в разных проектах.

Пример: Описание способа проверить, что тест падает до исправления и проходит после.

Факт двух прогонов служит доказательством регрессии, а команда зависит от принимающего проекта.

Пример иллюстративный. Структура создана заранее; рабочие материалы категории ещё предстоит собрать и проверить.


## Согласованная структура, 2026-10-06

После миграции acceptance хранит критерии, tests — исполняемые тесты, evidence — результаты. В корне testing остаются технические manifests зависимостей и pytest-конфигурация. Например, tests/test_entrypoint_portability.py проверяет два режима установки; для пустого project это иллюстративный пример.
