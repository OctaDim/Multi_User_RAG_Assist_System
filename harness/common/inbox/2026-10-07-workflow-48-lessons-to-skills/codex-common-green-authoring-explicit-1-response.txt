**Выбор формата:** самостоятельный повторяемый сценарий диагностики CSV с точным trigger подходит для компактного **lazy skill**. Сначала проверяется существующий владелец; если сценарий уже покрыт, дополняется его ресурс. В `description` помещается trigger, в тело — обязательный алгоритм, условия остановки и наблюдаемый результат. Существенные подробности выносятся в reference с точным условием чтения.

Просьба коллеги об обязательности алгоритма не обосновывает always-loaded rule. Для такого правила нужно назвать конкретное ошибочное действие, возможное **до выбора скилла**; тогда допустим короткий guard и указатель на процедуру. Дедлайн этого требования не отменяет.

**Критерии проверки:**

- Зафиксировать контракт: применимость, действия, результат, недостающие данные, разрешения и остановки.
- RED без новой инструкции → компактный кандидат → GREEN; после правок повторить проверки.
- Проверить явный вызов, неявный выбор по trigger, чтение собственного reference и отсутствие загрузки на посторонней задаче.
- Отдельно проверить исключение human README в чтении правил, загрузчиках и поведении.
- Проверить Codex и Claude отдельно в режимах common-only и common+project; project-only должен отклоняться.
- Для скилла обязательны `quick_validate.py` и применимые внешние проверки; статическая валидность не доказывает нативное поведение.
