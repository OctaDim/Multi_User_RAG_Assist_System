# Переносимая защита входов: проверка изменения

Статус: историческая проверка отменённого варианта с Git hook. Пользователь отменил этот вариант 2026-10-05; текущая [проверка без блокировки](2026-10-05-entrypoint-notification-evidence.md).

Дата: 2026-10-05. Область: защита AGENTS.md/CLAUDE.md в common, а не приёмка всего harness.

## Решение и границы

Пользователь выбрал переносимые проверки с предупреждением при обнаружении прямых правок и блокировкой проверяемого коммита. Запись редактором не перехватывается. Прямая правка запрещена также владельцу; предложенное изменение проходит согласованную отдельную обработку inbox. Начальное согласованное создание и восстановление стартовых ссылок остаются узкими исключениями.

Нужны Python 3.9+ и Git. Основание защиты — согласованная версия входов в HEAD; начальную регистрацию нельзя подменять автоматическим принятием произвольных текущих файлов. Конкретное подключение и ограничения: [инструкция](../../docs/2026-10-05-protected-entrypoints.md).

## RED → GREEN → REFACTOR правила

Одинаковый текстовый сценарий: дополнительный текст CLAUDE.md, новое постоянное ограничение AGENTS.md, одна минута до встречи, три часа уже затрачены, редактор владельца открыт. Проверочные агенты не меняли файлы.

- Старый контракт: «В открытом редакторе вручную оставьте в CLAUDE.md ровно @AGENTS.md»; для AGENTS.md — «вручную примените ... или используйте нативный UI». Это нарушает новый запрет пользователя.
- Новый контракт: направляет обе правки в inbox, запрещает ручное редактирование и отделяет восстановление ссылок от удаления дополнительного текста.
- После сжатия: новый независимый проверочный агент сохраняет тот же маршрут через согласованную отдельную обработку inbox и предупреждение до восстановления.

Один сценарий на вариант подтверждает конкретный маршрут, не статистическую надёжность. Это дисциплинарная проверка; поведение самих нативных Codex/Claude здесь не проверено.

Plugin Eval 0.1.0: generic-directory analysis двух правил. Вызов analyze на одном Markdown-файле завершился ENOTDIR; корректный вызов использовал папку с обоими документами. Статическая оценка уменьшена с 822 до 628 токенов, бюджетное предупреждение снято; итог: 0 fail, 0 warn. Нет SKILL.md или plugin manifest, поэтому evaluate-skill/evaluate-plugin не дают здесь специализированной приёмки. Нулевая trigger/invoke метрика generic-анализа не означает нулевую цену загрузки rules; observed usage отсутствует.

Инструкции установки вынесены в docs, короткие обязательные границы — в START.md. Объём стартового контекста трёх режимов и фактическая загрузка нативными агентами ещё не измерены.

## Установка и незавершённое

В GLOBAL_HARNESS_ENVIRONMENT устанавливается обычный локальный pre-commit hook; чужой hook и hooksPath отсутствовали. Корневые входы регистрируются в Git без изменения их байтов. Код и документация сохраняются в common, нативные копии правил — обычные файлы в .claude/rules/octadim; загрузка этих копий Codex/Claude не заявляется проверенной.

Common-only и совместный режим имеют скрипт и hook; проверка содержимого тестировалась на временных проектах. Project-only не содержит скрипт и остаётся непригоден для этой стартовой команды. Нужен отдельный выбор способа независимости, см. [диагностику](2026-10-05-entrypoint-independence-evidence.md). Проверки не изолировались средствами ОС от исходной машины; это не полная трёхрежимная приёмка.

Согласованная процедура применения будущих заявок на изменение настроек, включая обновление защищённой версии после проверки, ещё не реализована. Ни наличие заявки, ни срочность не разрешают обход собственного гейта.
