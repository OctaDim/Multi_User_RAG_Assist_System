# Восстановление ссылок должно сохранять исходные переводы строк

Подтверждённый опыт: 2026-10-05, пункт 2 аудита входной проверки.

Ошибка проявлялась при добавлении отсутствующей ссылки в AGENTS.md с CRLF:
проверка сообщала успех, но превращала исходный пользовательский текст в LF.
Добавление импорта в CLAUDE.md использовало тот же путь нормализации.

Причина — текстовое чтение с универсальными переводами строк и последующая
запись нормализованного текста. Сохранения смысла недостаточно для узкого
разрешения дописать только стартовые подключения.

Исправление в ensure_entrypoint_links.py: декодирование/кодирование UTF-8 без
нормализации, сохранение исходного содержимого при добавлении строк, выбор LF/CRLF
для вставки по первому переводу каждого файла. Распознавание CRLF-импорта и
сравнение с Git учитывают CRLF, чтобы следующий запуск не создавал дубликатов
и ложных предупреждений. Common-исходник и автономная project-копия равны.

Проверка: `.venv/bin/python -m pytest`.
Регрессии выполняют реальный ремонт временных файлов и сравнивают исходные байты,
переводы вставок, импорт, повторный запуск и предупреждения относительно Git.
Полные результаты и область проверки — в [доказательствах](../testing/evidence/2026-10-05-entrypoint-crlf-evidence.md).
