# Структура harness и постоянные даты создания

Дата создания: 2026-10-06. Каркас и польза новых категорий для всех проектов
подтверждены пользователем при обработке common inbox-заявки.

При создании, размещении, изменении или переносе материалов harness используй
одинаковые категории common/project: checks, scripts, testing, specs, docs,
decisions, inbox, rules, skills, base, lessons, handoffs. В testing предусмотрены
acceptance, tests, evidence. INDEX.md и START.md сохраняют стабильные имена.
Каждой папке нужен README.human.md с пояснением и примером; тела этих файлов
исключаются из агентского контекста, поиска и оценки.

checks хранит исполняемые проверки harness и инструкции их запуска; scripts —
служебные скрипты; testing/tests — исполняемые тесты; testing/acceptance —
критерии; testing/evidence — отчёты и сырые свидетельства. specs хранит
спецификации согласованного поведения, docs — объяснения и планы. Решения,
ошибки/решения, базовые контракты и передачи задачи относятся соответственно
к decisions, lessons, base и handoffs. Общие знания остаются в common,
проектные — в project; старые кандидаты inbox не преобразуются массово.

Файлы знаний в specs/docs/decisions/base/lessons/handoffs и свидетельства
в testing/evidence получают префикс YYYY-MM-DD с датой создания материала.
Правка не меняет дату имени. Связанные файлы одного материала размещаются
в предметной папке с датой создания этой папки; даты вложенных файлов
независимы. Новая папка создана 2026-10-06, новый JSON добавлен 2026-10-07:
папка сохраняет 2026-10-06, JSON получает 2026-10-07. Документ, созданный
2026-10-04 и изменённый 2026-10-06, сохраняет в имени 2026-10-04.

Для старого материала используй доказуемую историю создания, учитывая
переносы и переименования, либо явно записанный факт создания. Дата проверки,
принятия решения, импортирующего commit или checkout mtime сама по себе
не доказывает создание. При неизвестной дате согласуй имя конкретного
материала с пользователем до переименования. Не придумывай дату.
Автоматическое обновление дат, watchers, hooks и обслуживаемый manifest дат
не применяются; история изменений остаётся в Git и содержимом материала.

Стабильные технические исключения: категории и их INDEX.md/START.md,
README.human.md, обязательный base/project-skeleton.json, исполняемые
Python/Node.js программы, test_*.py, acceptance.md, pytest.ini,
requirements.txt/requirements.lock и нативные имена правил/скиллов вместе
с их служебными ресурсами. Папка docs/plans сохраняет роль раздела планов.

Common обязателен и автономен от исходного приложения. Common-only создаёт
нейтральный project по явно сохранённому base/project-skeleton.json.
Common+project сохраняет существующий project; обычный старт не дополняет
его даже при новой редакции шаблона. Project-only даёт отказ до записи.
Изменение каркаса по-прежнему требует отдельной common inbox-заявки,
отдельного решения и отдельного подтверждения пользы для всех проектов.
Текущий project дополняется только разрешённой разовой миграцией.

При переносе составляй карту старых/новых путей, сохраняй исходные hashes
и сырые отчёты, исправляй рабочие ссылки и команды. Исторические команды
и результаты не переписываются как новая проверка. После переноса проверяй
тесты, ссылки, оба режима установки, идемпотентность и отказ project-only.
Изменённые инструкции и ресурсы получают новые отдельные статусы Codex/Claude;
неполная проверка сохраняет действующий gate публикации текущей версии.
AGENTS.md/CLAUDE.md напрямую не редактируются.
