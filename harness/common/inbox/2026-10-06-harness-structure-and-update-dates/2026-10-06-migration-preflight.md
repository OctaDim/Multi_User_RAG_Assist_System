# Подготовка миграции структуры harness

Дата создания: 2026-10-06.

Выполнение заявки разрешено общим запросом выполнить inbox. Перед включением
новых папок в общий каркас ещё нужны два отдельных подтверждения R10.

## Конкретное изменение каркаса

[Кандидат JSON](2026-10-06-project-skeleton-candidate.json) добавляет к десяти
действующим категориям `scripts/` и `specs/`, а в `testing/` — `acceptance/`,
`tests/`, `evidence/`. Каждая папка получает человеческое пояснение.
Используется существующий генератор; новые механизмы синхронизации не нужны.

После согласования действующие common/project дополняются разово в рамках
этой миграции. В последующих установках common-only создаётся новый нейтральный
project с полным разрешённым каркасом. Обычный старт с существующим project
сохраняет его файлы и не дополняет его автоматически.

[Предварительная проверка кандидата](2026-10-06-template-preflight.json)
прошла в двух временных установках: создание всех 15 каталогов с пояснениями
в common-only; сохранение всех исходных файлов в common+project; повторный
запуск сохраняет байты обоих project. Это проверка совместимости шаблона,
а не итоговая приёмка миграции или нативных инструкций. Канонический шаблон
не изменён.

## Переносы и даты

[Инвентаризация](2026-10-06-migration-preflight.json) фиксирует 79 действующих
ресурсов, hashes, сведения Git и упоминания дат. Старые inbox-снимки исключены
из массовой структурной миграции.

Основные переносы: пять тестовых модулей из checks в testing/tests;
acceptance.md в testing/acceptance; Node.js launcher в scripts; результаты
проверок в testing/evidence. Связанные MD/JSON объединяются в предметные
папки. Новые результаты pytest и uv учитываются вместе с прежними материалами.

Стабильные технические имена сохраняются. Даты правок, проверок, принятия
решения и импортирующих commits сами по себе не объявляются датами создания.
Заменитель `<creation-date>` в предварительной карте — нерешённое происхождение,
а не предложенное имя файла. До переноса такие даты должны быть доказаны
историей создания либо согласованы для конкретного материала. Имена после
правок не меняются; автоматического обновления дат не будет.

План обновлён под уже выполненную миграцию на pytest; прежний plan-review.json
сохранён как проверка прежней версии. Итоговые проверки схемы, путей, ссылок,
тестов и нативных инструкций проводятся после реализации и не заявляются
этим preflight.
