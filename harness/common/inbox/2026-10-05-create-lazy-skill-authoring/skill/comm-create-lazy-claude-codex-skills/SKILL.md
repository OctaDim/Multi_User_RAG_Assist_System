# Create and publish lazy Claude-Codex skills

Keep discovery in name/description; load instructions and resources only for the selected task.

1. Establish the requested outcome and destination. Read [validation and publication](references/validation-and-publication.md) for creation or promotion. Without explicit canonical placement, preserve context, required result and the complete skill in a separate dated inbox folder.
2. Use a lowercase hyphenated name under 64 characters; folder/frontmatter names match. Consult [placement](references/placement-contract.md) when choosing ownership, namespace, Git treatment or mirrors.
3. Use skill-creator, writing-skills and the applicable external evaluation workflow in the reference. Missing or failed checks mean **unverified**, with a warning and installation offer.
4. Before publication repeat validation for the final version. Missing/failed checks require explicit permission for **unverified publication**; a transfer request is not that permission. Keep the status unverified after an exception.
5. After the gate, save the canonical folder and full ordinary copies in both native skill roots; edit once and compare copies. Verify native discovery and behavior separately.

Never read README.human.md bodies, use symlinks, edit protected entrypoints, or let personal guidance skip canonical requirements. Stop the dependent publication until required permission arrives.
