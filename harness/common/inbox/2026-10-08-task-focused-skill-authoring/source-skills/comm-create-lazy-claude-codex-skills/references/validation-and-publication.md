# Validation/publication

Before inbox recording/processing read
`harness/common/skills/comm-process-harness-inbox/SKILL.md`: stage permissions,
full candidate, context, status and permanent storage. New folders: immediate human guides; exclude bodies.

Authoring/testing: record applicability, required actions and observable compliance,
including limits/approvals/stops/missing data; name the test scenarios. Follow:
saved contract → RED without new instructions → compact candidate → GREEN;
retest after edits, never shrink already-compact material artificially.
Before plugin-eval read [evaluation](evaluation.md):
use its separate Node.js filter. Check rule reading, loader exclusion and behavior separately; instructions
do not block file access.

Applicable skill-creator and external validation checks are mandatory in every
project; unavailable checks remain unverified. Helpers (portable): using-superpowers;
openai-docs official sources; skill-creator design/final quick_validate.py;
writing-skills behavioral RED–GREEN–REFACTOR; plugin-eval start/evaluate-skill
analyze; improve-skill brief→required/recommended fixes→re-evaluate/compare;
plugin-management for integration/install. Evaluate-plugin only real manifests.
Do not publish/test an artificial long draft merely to shorten it; measure the
compact candidate itself. Every moved detail retains a tested when-read pointer.
Plain rules: skill-creator scope/no duplication, [content](content-contract.md),
conventions/conflicts/resources/compactness; no skill-only validator. Generic
analysis is not skill/plugin/native proof. Missing tools: warn, offer authorized
install, unverified; installed ≠ verified. Authorize benchmark/config/dependency writes.

Each final version: both agents/modes, listing, explicit own-resource invocation,
implicit selection, unrelated non-loading and preserved behavior. Common-only:
neutral project; combined: preserve files; project-only: refusal. Installation/template changes: open
`harness/common/skills/comm-install-harness/SKILL.md`; never infer a shared template.

Report date/version/files/commands/tools/agent versions/scope/contract/compactness;
pass/fail/not-run/N/A+reasons, findings/missing tools/next steps, agent-mode statuses. Static tokens ≠ measured usage; equality ≠ native proof. Verified: all mandatory current checks pass, no correctness/discovery/behavior gaps.
Edits reset statuses; repeat all current checks before publication. Keep in inbox until this version/source/native paths are authorized; unavailable/failed checks require explicit permission for
this unverified version. Transfer/prior success/deadline is not a waiver;
exceptions retain statuses. For approved unverified publication record the actual
permission and confirmation, current version and exact source/native transfer scope. After gate [placement](placement-contract.md) and
Git/native checks; new failures reset gate. Evidence: testing/evidence (not checks); temporary candidate/history: inbox.
Permanent rationale must survive inbox deletion. For suite commands/configuration
read `harness/common/skills/comm-install-harness/references/testing.md` only when
running/installing the harness tests.
