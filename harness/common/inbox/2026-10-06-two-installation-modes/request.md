# Два режима установки harness

Дата возникновения: 2026-10-06. Обстоятельства: пользователь уточнил пункт 2 аудита validation-and-publication.md и явно попросил изменить модель переносимости через using-superpowers, ce-brainstorm и ce-plan.

Причина: при переносе общих знаний в новый проект нужно получать полный пустой project без копирования материалов старого проекта и ручной очистки. Отдельный project-only исключается: project опирается на common.

Требуемый результат: (1) перенос только harness/common автоматически создаёт и проверяет полный нейтральный каркас harness/project из сохранённого актуального источника внутри common; (2) перенос common+project распознаёт существующий project и сохраняет его материалы; (3) project-only больше не считается поддерживаемой установкой. Обновляются действующие правила, документация и проверки. Исторические свидетельства не выдаются за текущую приёмку.

Решение пользователя 2026-10-06: каркас создаётся автоматически по общему описанию внутри common. Его состав не выводится из дерева project. Новая общая категория, например specs/, становится частью следующей версии шаблона только через отдельную заявку в common inbox, отдельное явное решение пользователя и отдельное явное подтверждение пользователя. docs/epl-import/ и другие папки конкретных задач автоматически в шаблон не попадают. Агент может предложить включение, но зависимое изменение останавливается до обоих пользовательских сообщений; отсутствие ответа не согласие. Следующие новые проекты получают обновлённый шаблон; существующие project не заменяются пустым каркасом.

Публикация кандидата отдельно проходит действующий gate: два независимых статуса агента, проверки текущей версии и разрешение на конкретное непроверенное исключение при необходимости. Запрос изменений не выдаётся за такое исключение.
