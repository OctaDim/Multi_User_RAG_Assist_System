# Два режима установки и проектный каркас

Применяется при создании, изменении, подключении или переносе harness.

1. Common — обязательный переносимый пакет; он не требует исходного приложения или материалов прежнего project. Project использует процедуры и проверки common и отдельно не устанавливается.
2. Режим 1: перенести только harness/common/. Стартовая проверка из common проверяет сохранённое описание base/project-skeleton.json и автоматически создаёт отсутствующий harness/project/: согласованные пустые категории, нейтральные INDEX.md/START.md и пояснения README.human.md. Рабочие материалы старого проекта не копируются.
3. Режим 2: перенести harness/common/ и harness/project/. Существующий project проверяется, пустой каркас вместо него не создаётся; его файлы не перезаписываются и состав по новой редакции шаблона автоматически не дополняется. Повреждённые обязательные ресурсы дают отказ.
4. Состав каркаса задаётся явно в common, не выводится из папок текущего проекта. Его изменение — через отдельную common inbox-заявку, отдельное явное решение пользователя и отдельное явное подтверждение пользователя о пользе папки для всех проектов. Агент может предложить категорию, но до обоих ответов останавливает её включение; отсутствие ответа не заменяет решение. Следующие новые проекты получают актуальную разрешённую редакцию.
5. Проверять оба режима в чистых временных установках без доступа к исходному проекту и авторским глобальным материалам. Для первого режима доказать создание полного нейтрального project, для второго — сохранение существующих файлов; отдельно проверять повторный запуск и отказ при отсутствии common. Отказ project-only — негативный контроль, не третий режим.
6. Ограничивать и проверять стартовый контекст отдельно для двух установок, включая автоматически созданный project в первом режиме. На старте — короткие ограничения и указатели; подробности — по задаче. Комплектность не означает чтения всего пакета. README.human.md в контекст не включать.
7. Знания между пакетами не дублировать. Конфликт common/project согласовать с пользователем и ждать ответа перед зависимым действием. Сохранять команды, результаты и ограничения; структурная проверка не доказывает нативное поведение Codex/Claude.

Основная проверка — common/checks/ensure_entrypoint_links.py. Старый путь project/checks/ensure_entrypoint_links.py может сохраняться как короткий вызов обязательной проверки common для совместимости существующих статичных входов; это не автономная копия и не поддержка project-only. В новом пустом каркасе этот старый путь не создаётся.
