# Decisions: принятые решения

Решения пользователя об архитектуре harness, защищённых входах, владении скиллами и правилами, согласовании и учёте выполнения заявок. Записи объясняют причину решения, его область и последующие уточнения.

Пример: inbox-execution-status.md разделяет разрешение создать заявку, разрешение выполнить её и статус проверки полученного материала.

Благодаря этому выбор номера варианта не подменяет отдельное разрешение, а выполненная заявка не выдаётся за полностью проверенный скилл.

Это пояснение для человека. При обычной работе агента его тело не входит в инструкции, поиск знаний или оценку скилла.
