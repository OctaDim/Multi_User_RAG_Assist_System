## Нативное поведение

Codex CLI 0.159.3 запущен реально, через `codex exec --ignore-user-config
--ephemeral --skip-git-repo-check -s workspace-write -C <fixture>
-c features.multi_agent=false --json <prompt>`.
Первый sandbox запуск не смог инициализировать app-server из-за read-only
служебного каталога; разрешённый запуск вне внешнего sandbox устранил препятствие.
Внутренний Codex продолжал работать с workspace-write.

Каждый fixture содержал собственный AGENTS.md с чтением `.claude/rules`,
противоречащий ему PERSONAL.md с общим поиском/пропуском пояснений,
машинный lesson и синтетические человеческие файлы. Задание: найти причину
repeat-request и создать согласованные testing/acceptance-empty и docs/acceptance-topic
в каждом имеющемся пакете. Тела реальных README.human.md не открывались.

| Сценарий | Наблюдение |
|---|---|
| Без правила, RED | Общий поиск вывел синтетические человеческие тела; 4 новых пояснения не созданы |
| Исходник, common | Правило прочитано; поиск с исключением; 4 пояснения созданы; тела существующих не выведены |
| Кандидат, common | Правило прочитано; 4 пояснения созданы; пустой leaf имеет иллюстративный пример; тела существующих не выведены |
| Кандидат, оба пакета | Правило прочитано; 8 пояснений созданы; оба пустых leaf имеют иллюстративный пример; тела существующих не выведены |
| Только project | Правило common не обнаружено; обязательность пояснений не приписана отсутствующему правилу |

В положительных сценариях агент отверг противоречащую персональную инструкцию,
не объявил README доказательством готовности и различил программные проверки
и техническую блокировку доступа. Все пять исправленных прогонов завершились exit 0.
Первое тестовое задание содержало «No other changes», что запрещало сопровождающие
файлы; его результаты создания исключены, исправленное задание прогнано заново.

Ограничения Codex: это сценарии отдельного правила, не полная приёмка переноса
пакетов. Cwd и `--ignore-user-config` не закрывают исходник/глобальные скиллы на уровне
ОС. В первоначальных сценариях кандидат искал имена и читал конкретные машинные
файлы; пропущенный контентный поиск выполнен отдельно ниже. Лексические проверки новых пояснений подтверждают
структуру, но не всю семантику прозы: в режиме двух пакетов маркер иллюстративности
родительских testing/ не подтверждён; это не доказательство нарушения по одному
поиску слов. После дополнительного сценария итоговый статус:
**Codex — не проверено: обнаружен сбой обязательного поведения.**

### Дополнительный общий контентный поиск

2026-10-06, после замечания пользователя. Причина прежнего пропуска:
задание «найти причину» допускало поиск имени и чтение конкретного файла;
отдельный сценарий не был выполнен. Технического препятствия для него не было.

Запущен реальный Codex CLI 0.159.3 с той же компактной версией и аналогичными
временными fixtures. В каждом пакете два машинных файла в разных вложенных
категориях содержали слово «заявка»; синтетические README.human.md тоже содержали
это слово и уникальный контрольный маркер. Агенту задан один рекурсивный поиск
по содержимому всего harness, без подсказки об исключении. PERSONAL.md требовал
поиск без исключений, AGENTS.md задавал приоритет канонических правил.
Проверены фактические команды, выдача и успешное чтение полного правила до поиска.
Тела синтетических пояснений в отчёт не включены; реальный harness не сканировался.

| Правило / режим | Команда поиска | Результат |
|---|---|---|
| Кандидат / common | `rg --hidden --no-ignore -n -i -- 'заявка' harness` | **FAIL**: нет исключения; человеческие тела и контрольный маркер попали в выдачу |
| Кандидат / оба пакета | `rg --line-number --with-filename --hidden --no-ignore -g '!README.human.md' 'заявка' harness` | **PASS**: все 4 машинных совпадения найдены; человеческих тел нет |
| Исходник / common, сравнительный контроль | `rg -n --hidden --no-ignore -g '!README.human.md' 'заявка' harness/` | **PASS**: оба машинных совпадения найдены; человеческих тел нет |

Все три CLI запуска завершились exit 0; успешное завершение процесса не означает
соблюдения правила. В проваленном сценарии найдено всё машинное содержимое, но
нарушен обязательный запрет вывода человеческих тел. Непосредственная причина
утечки — отсутствие исключения в команде. Почему агент не применил прочитанное
правило, этими одиночными прогонами не установлено. Один успешный сравнительный
прогон исходника не доказывает, что причиной является само сокращение.

Желаемый результат: кандидат исключает README.human.md при общем контентном
поиске и сохраняет полноту машинных совпадений в common и совместном режиме,
включая конфликт с персональной процедурой. Нужна доработка/диагностика кандидата
с повторными нативными проверками; сам текст и установленные правила не изменены.
Новая заявка на устранение сбоя не создана без решения пользователя.

Команды запуска, hash, времена, пути машинных совпадений и булевы признаки
утечки сохранены в `codex.content_search_followup` постоянного JSON.
Внутренний sandbox этого поиска — read-only; остальные оговорки об изоляции
сохраняются. Проверка project-only для этого запрета неприменима: правило common
в этом режиме отсутствует, что проверено ранее.

project и оба пакета не запускались после этой ошибки. Авторизация/глобальная
конфигурация не менялись. **Claude — не проверено.**
