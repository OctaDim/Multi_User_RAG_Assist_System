# Приёмка двух режимов установки harness

Требования согласованы: 2026-10-04. Перенесены: 2026-10-05. Полная приёмка ещё не выполнена.
Объект: [структурный контракт](../../rules/comm-package-independence.md).

| Режим | Условия проверки | Требуемый результат |
|---|---|---|
| Только common | В чистый проект скопирован только common, project отсутствует; исходный проект недоступен | Стартовая проверка создаёт полный нейтральный project из общего описания, без рабочих материалов прежнего проекта |
| Common+project | Перенесены оба пакета, project содержит рабочие материалы | Проверка сохраняет существующий project побайтно и не создаёт вместо него пустой каркас |
| Нарушенная комплектность | В изолированной копии удалён обязательный локальный ресурс или повреждена ссылка | Соответствующая проверка замечает повреждение и даёт диагностируемый отказ; зелёный результат на пустой выборке не считается доказательством |

Приёмка должна отдельно показать комплектность, подключение к Codex/Claude и поведение. Проверка существования файлов не доказывает чтение агентом, а успешный запуск инструмента не доказывает обязательность его запуска.
Ссылки на источники происхождения опыта не должны становиться скрытыми обязательными зависимостями установленной папки. Возможности и ограничения живого проекта проверяются отдельно от автономной работоспособности пакета знаний; отсутствие приложения в чистом временном проекте нельзя выдавать за успешную проверку его поведения.
Существующие глобальные скиллы автора или соседние каталоги не должны маскировать неполноту тестовой копии.
Формат подключения, внешние prerequisites и точные бюджеты ещё предстоит согласовать. Здесь зафиксированы требования пользователя, а не выбранная реализация.

## Состав проверок, уточнённый 2026-10-05

### Файлы и перенос

Для каждого из двух режимов проверять все локальные Markdown-ссылки, пути к справочным файлам и ресурсам, команды и скрипты, требуемые инструкциями. Отсутствие ресурса, выход обязательной ссылки за границы пакета или скрытая зависимость common от исходного project должны давать ошибку. Пути назначения установки в корне нового проекта отличаются от ссылок на обязательные исходные ресурсы; установка не должна читать соседний или исходный пакет. Внешние URL проверяются отдельно и не служат доказательством локальной комплектности.

Чистые временные копии проверяются без доступа к исходному проекту и его материалам. Новый cwd и пустой HOME сами по себе не обеспечивают изоляцию на уровне ОС. Негативные контроли: повреждённая ссылка, отсутствующий ресурс, различающиеся зеркала, игнорируемый общий материал, неожиданная зависимость от глобального авторского скилла.

### Реальное обнаружение и применение

В каждом режиме запустить отдельно Codex и Claude Code в чистом окружении с установленными нативными копиями. Проверить уникальный тестовый скилл: наличие в списке, явный вызов и контрольное действие с использованием ресурса из его собственной папки. Автоматический выбор по description проверять отдельно; результат зависит от задачи и не заменяет явный вызов. Для правил отдельно проверяется загрузка обязательного ограничения до выбора процедуры и отсутствие обхода через индивидуальный материал.

Для каждого режима и агента сохранить версию, команду или способ запуска, наблюдаемый результат и ограничения. Невозможность запуска означает «не проверено». Совпадение файлов, validator или generic Plugin Eval не означают обнаружения нативным приложением. Установленные authoring skills и глобальные конфигурации не должны скрывать недостающие ресурсы.

Статусы скилла или правила фиксировать отдельно: «Codex — проверено/не проверено»,
«Claude — проверено/не проверено», с результатами каждого обязательного режима.
Полная проверка требует «проверено» у обоих для одной итоговой компактной версии
и успешных общих проверок. Без неё перенос в канонические и нативные папки —
только с явным разрешением и подтверждением пользователя; статусы не повышаются
из-за разрешения. [Порядок и отчёт](../../docs/2026-10-05-compact-authoring.md).

### Начальный контекст

Отдельно измерить два режима: начальные обязательные указатели и ограничения, а также нативный каталог названий/описаний скиллов. Объём всех файлов пакета не является стартовым контекстом. Инструкции установки, подробности процедур и тела README.human.md не должны попадать в стартовую загрузку. Численные бюджеты и окончательный способ подключения ещё не согласованы.

## Проектный каркас и исключённый режим

В первом режиме проверить все согласованные категории, нейтральность INDEX/START, наличие человеческих пояснений и повторный запуск без изменений. Во втором сохранить байты существующих проектных материалов и отдельно проверить, что новая редакция общего шаблона не дополняет проект автоматически. Проектные подпапки, например docs/epl-import/, не экспортируются в шаблон.

Изменение состава — через отдельную common inbox-заявку, отдельное явное решение и отдельное явное подтверждение пользователя; предложение или отсутствие ответа не разрешают добавление. specs/ проверяется только в синтетической разрешённой редакции fixture, не добавляется в действующий состав без решения.

Отсутствие common даёт отказ: project-only является неподдерживаемым состоянием, не третьим режимом установки. Старый проектный путь проверки при совместной установке вызывает common; его автономная реализация отменена. Проверить такую прежнюю команду без редактирования пользовательского AGENTS.md.

Исторические свидетельства трёх независимых режимов сохраняются как история и не подменяют текущую приёмку. Новые результаты, hashes и реальные ограничения фиксируются отдельно.
