# Project: материалы EPL

Пакет знаний исходного проекта EPL с теми же десятью категориями, что у common. Сейчас в docs/ хранится первичный анализ исходника, а в checks/ — автономная обычная копия проверки входа. Есть собственные INDEX.md и START.md.

Пример: docs/epl-harness-audit.md перечисляет наблюдавшиеся механизмы EPL и ограничения их проверки.

Отчёт описывает источник, а не вводит его частные команды или ограничения как универсальные правила. Копия проверки входа работает без установленного common.

Полный перенос знаний EPL и приёмка проектного пакета не завершены. Остальные предметные категории пока содержат только пояснения; их примеры иллюстративны.

Это пояснение для человека. При обычной работе агента его тело не входит в инструкции, поиск знаний или оценку скилла.


## Согласованная структура, 2026-10-06

После миграции используются 12 категорий: checks, scripts, testing, specs, docs, decisions, inbox, rules, skills, base, lessons, handoffs. В testing предусмотрены acceptance, tests, evidence. Даты в именах знаний означают создание и не меняются при правках.
