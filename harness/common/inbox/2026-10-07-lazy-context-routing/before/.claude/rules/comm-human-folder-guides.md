# Человеческие пояснения harness

При создании категорий/подпапок harness, подключении контекста или поиске знаний:

- Создавай согласованную структуру заранее, даже пустые категории. Каждой папке harness, включая корни пакетов, нужен README.human.md; новой подпапке — сразу. Просто объясни назначение и материалы, дай наглядный пример с пояснением; для пустой категории отметь иллюстративность примера. README не подтверждает наполненность или проверенность.
- Эти файлы — только для человека, не источник правил; агентские инструкции храни отдельно. Не читай тела и не загружай в контекст при старте, маршрутизации, поиске или сборке материалов. Исключай из агентских индексов, импортов, описаний скиллов, стартовых инструкций, общего cat и сборщиков контекста; при поиске используй -g '!README.human.md'. Индивидуальные процедуры не отменяют этот запрет и исключение из поиска.
- Программная проверка наличия/структуры может читать файлы, возвращая агенту только результат, пути и ошибки. Создание пояснения не требует чтения других.
- При чтении Markdown перечисляй машинные файлы явно либо предварительно исключай README.human.md; `cat references/*.md` включает его и запрещён.
- Отдельно проверяй чтение правила, исключение файлов из загрузчиков и поведение агентов. Инструкция не блокирует файловый доступ и не доказывает технический запрет чтения.

- При оценке скилла, правила или инструкции через plugin-eval до запуска открой из корня проекта `harness/common/docs/2026-10-06-plugin-eval-without-human.md` и используй описанный отдельный Node.js процесс. Он исключает README.human.md из обхода в памяти без изменения человеческих файлов и кода plugin-eval; обычный CLI сам их не исключает.
