Codebase Context

Цель портала — проверяемые ответы по личной библиотеке, а не просто чат. Сохраняются один backend, async FastAPI, отдельный worker, PostgreSQL/pgvector, LangGraph и независимый frontend через API. Пробы локальной пары E5/Qwen были синтетическими и односессионными.

Новые ограничения уже согласованы: 12 активных независимых контекстов и продвижение до 3 запросов за шаг; отдельные права форматов и рукописного OCR; пять персональных квот; глобальные изменения только super_admin, персональные лимиты доступны admin; disabled=True блокирует доступ. Во время отдельно разрешённого бесплатного fallback проверяются скорость и качество локальной модели, после прохождения обоих выполняется возврат. Эти требования не являются доказанными возможностями.

Остаются открытыми поддержка runtime и память для 12 контекстов по 4096 токенов вместе с остальными сервисами, численный порог скорости, уменьшение живых лимитов, сохранение и приоритет настроек после перезапуска, права изменения форматов/OCR и правила незавершённых операций. Параметры модели, требующие перезапуска, видны super_admin, но недоступны для изменения; backend соблюдает то же ограничение.

1 — Полезный результат до начала генерации

S192/100
Description
Показать владельцу доступные найденные фрагменты, пока генеративный ответ ждёт допуска или вычислений. Пользователь может уже решить задачу чтением оригинала и отменить свою генерацию; рядом видны состояние ожидания и продвижение ответа, а оператор может проверить справедливость по интервалам между ходами. Это не завершённый ответ модели и не обход очереди: момент поиска и его нагрузка требуют отдельного выбора.
Axis
A. Скорость, справедливость и доступность ответов
Basis

direct: RAG-11/26: очередь и отмена генерации, реестр, строки 37/52 и 62–71. Исторический критерий: «Ссылка открывает доступный документ и использованный фрагмент» (idea-review, строка 70).

reasoned: точный фрагмент иногда решает задачу раньше генерации; это гипотеза пользы. Досрочный поиск и отображение пауз не являются уже принятыми функциями.

Rationale
Сокращает бесполезное ожидание без замены выбранной LLM и даёт практический смысл прозрачной очереди.
Downsides
Поиск до допуска генерации сам расходует CPU и память. Нужно выбрать момент поиска и способ отмены ожидающего запроса; ранние фрагменты могут оказаться недостаточными. Не обещать время ожидания и не менять 12/3 ради этой идеи.

2 — Паспорт оснований и границ ответа

S291/100
Description
У ответа показать фактическую область поиска, использованные фрагменты и различие между тем, что буквально сказано в документе, и выводом из нескольких оснований. Если данных недостаточно, объяснить, какие выбранные документы ещё не готовы либо исключены, и предложить явный следующий шаг владельцу. Готовность документа не означает, что поиск проверил каждую его строку; область не расширяется автоматически.

3 — Рукопись, которую можно сверить с оригиналом

S387/100
Description
Связать распознанный текст с исходной страницей и показывать владельцу карту страниц с проблемами извлечения. Дать необязательную адресную сверку и исправление важных фрагментов — чисел, дат, фамилий, отрицаний — сохраняя оригинал и связь с цитатой. Уверенность OCR лишь направляет внимание; она не гарантирует правильность и не делает ручную проверку обязательной для каждой загрузки.
Axis

Basis

Description

5 — Квота помогает собрать допустимую пачку

G1884/100
Description
Перевернуть предположение «лимиты существуют только для отказа»: персональные ограничения могут помочь владельцу выбрать, что загрузить сейчас. Кандидат — предварительный разбор выбранной пачки по всем пяти квотам с предложением нескольких понятных способов уменьшить её; итоговый набор выбирает пользователь. Предварительная оценка не резервирует успех и не заменяет backend-проверку при параллельных загрузках; сохранённые документы не удаляются.
Axis
C. Путь документа от загрузки до пригодного источника
Basis

direct: RAG-13, реестр, строки 120–125: все пять лимитов персональные, backend учитывает параллельные загрузки.

reasoned: несколько независимых ограничений удобнее разобрать до серии неудачных загрузок. Подбор пачки — новая гипотеза удобства, а предварительный расчёт не гарантирует допуск.

Rationale
Владелец получает способ продолжить загрузку нужных источников, сохраняя свои файлы и не выполняя серию пробных запросов.
Downsides
Не все сведения о файле известны до обработки; проверка страниц PDF может быть дорогой. Предварительный выбор не резервирует квоту и не гарантирует успех при параллельных загрузках. Пользователь решает, какие файлы оставить; уже сохранённые документы не удаляются.

6 — Искать фрагмент, который опровергает удобный ответ

G1982/100
Description
Перевернуть предположение «RAG должен подтвердить найденный вывод»: владелец может явно попросить поискать противоречие в том же выбранном наборе. Кандидат — отдельный пользовательский вопрос, возвращающий доступные фрагменты за и против утверждения с различиями даты, объекта или условия, когда они подтверждаются источниками. Отсутствие найденного опровержения не доказывает истинность; это ручной новый запрос, а не отложенная автоматическая перепроверка старых ответов.
Axis

7 — Возврат локальной модели без разрыва ответа

G0277/100
Description
Автоматический возврат с разрешённой внешней генерации на локальную уже согласован, когда одновременно пройдены проверки скорости и качества, но судьба текущих и ожидающих ответов открыта. Предлагается обсуждать границу переключения как пользовательское правило: начатый ответ остаётся целостным в своём маршруте, а новые допущенные запросы получают актуальный маршрут после повторной проверки доступа и условий передачи данных. Правило не разрешает первичное внешнее переключение и не предполагает запуска проб сейчас.
Axis
A. Скорость, справедливость и доступность ответов
Basis

direct: RAG-31, реестр, строки 191–193: возврат при прохождении скорости и качества; строки 203–207: «поведение незавершённых ответов при смене маршрута ещё не определено».

reasoned: целостность начатого ответа и актуальный маршрут новых запросов могут быть полезной границей переключения. Это кандидат политики, а не согласованная судьба активных ответов.

Rationale
Незаметная смена генератора посреди текста может испортить продолжение и усложнить понимание, какой маршрут получил контекст; очередь создаёт отдельный момент для безопасного выбора.
Downsides
Имеет смысл только после отдельно разрешённого бесплатного fallback. Частота проб, скорость и качество, момент возврата и судьба очереди ещё требуют выбора. Целостность ответа не даёт права продолжать его после блокировки или отзыва согласия; нельзя добавлять автоматический исходящий fallback.
