Статус: исправления реализованы и проверены. Продолжение согласованного рефакторинга; прямые поправки пользователя от 2026-10-19 заменяют прежний запрет ответов без источников.

Исходная структура — секция A в [сохранённой исходной схеме](2026-10-19-frontend-layout-reference.html), версия ce-brainstorm 2026-10-18/rag-layouts-v1; [снимок сравнения](../testing/evidence/work/2026-10-19-variant-a-reference-comparison.png). Последний выбор пользователя — A; C не применяется. Исходник/снимок скопированы без редактирования. Это утверждённая структура, а не утверждение об одобрении каждым пользователем цветов или шрифтов. Существующее оформление сохраняется; новый визуальный стиль не вводится.

## Поведение

Нажатие «Новая беседа» открывает локальный черновик; пустые серверные записи не создаются при каждом нажатии и не показываются в списке. Регистрация не создаёт пустую беседу. При первой отправке создаётся беседа с устойчивым клиентским ID; повтор после неизвестного результата создания идемпотентен. Прежние пустые записи не удаляются автоматически.

Пустой выбор и отсутствие готовых доступных документов означают обычный ответ LLM без retrieval. Режим фиксируется при приёме вопроса; поздняя загрузка документов не меняет уже принятый запрос. При наличии готовых документов пустой выбор по-прежнему использует все доступные готовые собственные документы. Явный выбор недоступных документов остаётся ошибкой, без скрытого перехода на общие знания. Ответ без документов подписан, не содержит выдуманных цитат; его история сохраняется для такого режима и не становится документальным основанием RAG.

SQL: сохраняются согласованные SQLAlchemy expressions, готовые модели/Alembic и Database/session lifecycle. Новая схема/миграция и изменения ownership/heartbeat guards не требуются.

Независимое ревью (variant_a_review) обнаружило потерю навигации к неподтверждённой первой отправке при New/reload и позднюю перерисовку меню старым аккаунтом. ## Границы результата

Новые проверки относятся к этому исправлению. Прежние40browser/415technical/492общих случаев не объявляются заново исполненными. Старые завершённые отчёты и три исторических отказа расширенных PDF/совместных нагрузочных сценариев сохраняются без переписывания. Общие/установленные инструкции harness, изменённые параллельно пользователем, не входят в коммит приложения. Конфигурация рабочей базы/SMTP, существующие данные и модели не подменяются тестовыми; тесты используют временную PostgreSQL и SMTP-приёмник.

Поле первой отправки восстанавливается после неопределённого результата: список показывает название отправленного вопроса с пометкой «Не подтверждено», а не пустой номер. Если snapshot уже подтвердил создание, повтор не требует нового POST создания. Поздний HTTP ACK после смены аккаунта проходит current guard и не перерисовывает старое меню. Независимое ревью подтвердило исправление обеих находок; новых важных замечаний не осталось.
