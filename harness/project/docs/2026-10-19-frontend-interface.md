# Интерфейс корпоративной базы знаний RAG

Основной экран — беседа в центре. По уточнению от2026-10-20 область истории увеличена в10раз относительно исходной высоты для данного экрана. При новом вопросе и обновлении ответа она прокручивается к последней информации; после возврата из оснований на телефоне виден конец ответа. Кнопка «Основания» открывает панель рядом с перепиской; на узком экране она занимает рабочую область, а «Закрыть» возвращает беседу. Действие «Показать основания» у ответа выбирает именно его сохранённые фрагменты и паспорт. Ссылка цитаты переводит фокус на исходный фрагмент. На узком экране индикатор «новые» сообщает о появлении оснований, пока панель закрыта.

Постоянное левое меню содержит «Беседы», «Документы», «Новая беседа» и последние беседы с названиями по первому вопросу; управление находится внизу и доступно по роли. На узком экране меню открывается кнопкой «Меню». Список бесед остаётся раскрытым, длинные списки прокручиваются внутри меню. «Новая беседа» открывает локальный черновик; серверная запись появляется при первой отправке. Пустые беседы не показываются и не получают порядковых номеров. Выбор источников расположен под названием беседы, над перепиской; он сворачивается при вводе вопроса. Состояние ответа и остановка находятся непосредственно над формой вопроса внизу. Заголовок источников всегда показывает режим поиска или число выбранных документов. Текст вопроса и выбор источников принадлежат каждой беседе и вкладке. Переходы по разделам и перезагрузка сохраняют черновик; выход, смена пользователя и закрытие вкладки очищают его по существующему контракту. Раздел после перезагрузки восстанавливается; новый вход открывает беседу.

Если ни один источник не отмечен, поиск использует все готовые доступные документы пользователя. Если готовых документов нет и источники не отмечены, LLM отвечает из общих знаний и истории обычной беседы. Загружать документы для такой отправки не требуется. Этот режим подписан «Без документов · LLM» и не содержит документальных цитат. Отметки ограничивают поиск выбранными документами. Исчезновение выбранного источника не включает поиск по всей библиотеке: недоступный выбор остаётся видимым до явного снятия. При приёме вопроса сервер фиксирует состав документов; новые документы входят в следующий вопрос. Рядом с полем вопроса показана причина недоступности отправки. При неопределённом результате отправки предусмотрена проверка той же операции, без автоматической новой генерации.

«Документы» объединяет загрузку, обработку, выбор режима OCR, отчёт об ошибке, оригинал, исправление текста и удаление. Обновление статусов сохраняет редактор. Если документ удалён в другой вкладке, несохранённый текст остаётся доступен для копирования, а сохранение в удалённый источник блокируется. Закрытие с несохранённым текстом требует решения; удаление показывает название и последствия и допускает отмену. Сохранённое исправление может ожидать публикации: это состояние отображается отдельно, повторное сохранение до публикации недоступно. После сетевой ошибки загрузки сначала обновите список и проверьте результат, затем при необходимости выберите файл заново.

«Управление» доступно администраторам в пределах роли. Оно содержит аккаунты, индивидуальные ограничения документов и, для суперадминистратора, глобальные настройки генерации с предпросмотром и сохранённой/применённой ревизиями. Чужая библиотека явно подписана, доступна для чтения и имеет возврат к своей. Её просмотр не меняет источники вопроса.

Кнопки и формы показывают выполнение и ошибки рядом с действием. Ошибка отправки видна у поля вопроса и относится к соответствующей беседе; переход в другую беседу не переносит её туда. Правка вопроса или новый выбор источников снимает прежнее сообщение. После отказа открытия можно повторить выбор беседы; при неизвестном результате первой отправки используйте «Проверить отправку»: повтор сохраняет ID беседы и исходную операцию, а новый набранный черновик остаётся в поле. При временном отказе публичной политики доступно «Повторить подключение», при ошибке остановки — повтор остановки. Общий таймаут API настраивается через `client.request_timeout_ms` в конфигурации фронта; поток событий сохраняет отдельный механизм восстановления соединения.

Приложение по-прежнему запускается через `python3 backend/main.py` и `python3 frontend/main.py`. Новые зависимости и сборщик JavaScript не нужны. Параметры установки описаны в [настройках приложения](2026-10-16-application-settings.md).
