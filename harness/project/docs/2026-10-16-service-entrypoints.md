# Запуск бэка и фронта

После подготовки окружения и конфигов из корня проекта:

```bash
python3 backend/main.py
python3 frontend/main.py
```

Каждую команду запускайте в своём терминале. `Ctrl+C` или SIGTERM останавливает соответствующий раздел. Бэк останавливает все запущенные им процессы, включая native worker модели; если один компонент неожиданно завершился, весь запуск завершается с ненулевым кодом.

Из другого рабочего каталога укажите абсолютный путь к main.py. Относительные пути внутри конфигов по-прежнему отсчитываются от `backend/` или `frontend/`.

## Однократная подготовка

1. Подготовьте Python 3.12 и зависимости: `uv sync --project backend --frozen`. Фронту достаточно Python 3.11+ со стандартной библиотекой; отдельные Node.js-сервер и сборка не нужны.
2. Подготовьте работающий PostgreSQL с pgvector и базу для приложения. Новый launcher подключается к ней; жизненным циклом самого PostgreSQL он не управляет. Существующие процессы приложения применяют готовые ревизии Alembic при старте.
3. Подготовьте существующие модели Qwen, multilingual-e5-small и OCR. Launcher проверяет наличие необходимых файлов; модельные проверки и OCR остаются в соответствующих обработчиках.
4. Скопируйте `backend/config/service.local.example.toml` в `backend/config/service.local.toml`. Заполните строку БД, пути моделей и, для регистрации с подтверждением email, внешний SMTP. При отсутствии SMTP существующие аккаунты могут использовать приложение, но отправка подтверждения не настроена.
5. При необходимости скопируйте `frontend/config/service.local.example.toml` в `frontend/config/service.local.toml` и измените публичные адреса.

Шаблон бэка показывает принятое расположение уже скачанных моделей в `.venv/rag-native-models/`. Это пример установки, не команда скачивания. Для другой установки укажите собственные пути. В SMTP-шаблоне и DSN используются заглушки; их нужно заменить до использования.

## Источники настроек

Каждый раздел читает общий `config/service.toml`, затем локальный `config/service.local.toml`, если он существует. Переопределения объединяются по ключам секций; неизвестный ключ считается ошибкой. Общие конфиги и шаблоны хранятся в Git. Рабочие `service.local.toml` исключены точными правилами `.gitignore`.

Альтернативный файл локальных переопределений можно передать через `--config /path/to/settings.toml`; он заменяет стандартный локальный файл, а не общий конфиг. Бэк также поддерживает селектор `RAG_SERVICE_CONFIG` для совместимости отдельных компонентов; `--config` имеет приоритет. Эффективный путь передаётся детям абсолютным, до смены рабочего каталога.

Launcher бэка формирует существующие `RAG_DATABASE_URL`, `RAG_MODEL_PATH`, `RAG_E5_DIR`, `RAG_OCR_DIR`, `RAG_OCR_MODEL_PATH`, `RAG_ORIGINALS_DIR`, `RAG_FRONTEND_ORIGIN` и SMTP-переменные из конфигурации. Эти значения имеют приоритет над одноимёнными унаследованными переменными. Существующие отдельные `rag-api`, `rag-generation`, `rag-documents` и тестовые component entrypoints сохраняются и продолжают поддерживать свой env-интерфейс.

### Бэкенд

| Секция | Назначение |
|---|---|
| `launcher.python` | Python подготовленного окружения; по умолчанию `.venv/bin/python`. Main сам переключается на него, без активации venv в терминале. |
| `api.host`, `api.port` | Адрес прослушивания FastAPI. |
| `api.frontend_origin` | Публичный origin фронта для CORS и ссылок подтверждения: схема, хост и порт, без пути. |
| `database.dsn` | Строка PostgreSQL URI или libpq conninfo; обязательна. |
| `database.ready_timeout_seconds`, `connect_timeout_seconds`, `retry_seconds` | Общий срок ожидания БД, предел попытки и интервал повторения. |
| `models.generation`, `embedding`, `ocr`, `handwriting` | GGUF генерации, каталог E5, каталог OCR и необязательная отдельная GGUF для рукописей. |
| `storage.originals` | Каталог оригиналов; относительный путь отсчитывается от backend. |
| `smtp` | Хост, порт, отправитель, режим TLS, учётные данные и timeout. Пустые host/sender оставляют отправку почты ненастроенной. |
| `smtp.ports` | Порты по режимам TLS для отдельно запускаемых компонентов без явной SMTP-переменной порта. |
| `supervisor` | Интервал контроля, время штатной остановки и время ожидания после принудительной остановки. |

Пароли и DSN задавайте только в локальном файле с ограниченным доступом. Launcher не выводит их значения. Не размещайте секреты в общих конфигах и шаблонах. Альтернативные файлы вне стандартного локального пути оператор также должен держать вне Git.

Профили моделей и их контрольные суммы остаются в `backend/config/ocr.toml`, настройки генерации/embedding — в `runtime.toml`, лимиты документов — в `documents.toml`. Это отдельные существующие владельцы настроек. Административные overrides сохраняются в БД.

### Фронтенд

| Ключ | Назначение |
|---|---|
| `server.host`, `server.port` | Адрес HTTP-сервера интерфейса. |
| `server.poll_seconds` | Интервал обработки остановки сервера. |
| `api.origin` | Адрес API, к которому обращается браузер; без `/api` и других путей. |
| `client.reconnect_ms` | Пауза перед повторным подключением к потоку событий. |

Порт `0` фронта допускает выбор свободного порта ОС; фактический адрес отображается при старте. Для обычной работы задавайте фиксированный порт, согласованный с `api.frontend_origin` бэка.

Браузер получает только `api.origin` и `client.reconnect_ms`, подставленные в HTML. Сервер разрешает index и JS/CSS из `src/`; конфиги, Python-код, обходы каталогов и symlink-пути не раздаются. При внешнем размещении статических файлов сервер развёртывания должен аналогично подставить два публичных значения вместо `__RAG_API_ORIGIN__` и `__RAG_RECONNECT_MS__`.

## Поведение запуска и диагностика

Бэк проверяет конфиг и файлы моделей, ждёт PostgreSQL, затем запускает documents, generation и API отдельными группами процессов. Сообщение `Backend started` означает создание процесса, а не готовность модели. Uvicorn начинает слушать после своего startup; generation становится доступной после загрузки модели и обновления существующего lease. OCR загружается при обработке документа.

При ошибке параметров исправьте ключ, указанный в диагностике. При недоступной БД проверьте DSN, сеть и состояние PostgreSQL. Занятый API-порт приводит к завершению API и остановке остальных компонентов. При занятом порте фронта main завершается с ошибкой. Launcher рассчитан на Linux, как и существующий generation supervisor с host fence.

## Технические проверки

Новые проверки находятся в `backend/tests/test_launch_configuration.py`, `test_backend_launcher.py` и `test_frontend_launcher.py`. Они используют реальные HTTP-сокеты, процессы и временный PostgreSQL. Проверка полного бэкендового main дополнительно требует `RAG_MODEL_PATH`, `RAG_E5_DIR`, `RAG_OCR_DIR`, указывающих на подготовленные модели; без них этот отдельный smoke пропускается. Проверки качества ответов модели не являются проверками запуска.
