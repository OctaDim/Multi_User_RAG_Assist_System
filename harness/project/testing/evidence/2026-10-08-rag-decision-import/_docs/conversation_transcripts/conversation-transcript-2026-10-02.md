Начальные настройки для проверки: один одновременно генерируемый ответ и контекст 2048 токенов. Размер файла весов меньше полного потребления RAM: дополнительная память нужна контексту, вычислениям и самому порталу.

[Спецификация AMD](https://www.amd.com/en/products/processors/laptop/ryzen-pro/8000-series/amd-ryzen-7-pro-8845hs.html).

### Пользователь

Я правильно понял, что Openrouter имеет ограничение на количество запросов? Какие еще полностью бесплатные или open-source альтернативы можно рассмотреть, чтобы иметь постоянный доступ к модели эмбедингов и LLM?

### Ассистент — ответ

Да, у OpenRouter есть ограничения. Бесплатный облачный API и открытая модель — разные вещи: модель можно скачать бесплатно, но её запуск требует чьих-то вычислительных ресурсов.

Для бесплатных моделей OpenRouter сейчас указаны:

- 50 запросов в сутки без покупки кредитов.
- 1000 запросов в сутки после покупки кредитов на $10.
- 20 запросов в минуту в обоих случаях.

Дополнительно провайдер модели может ограничивать нагрузку. При использовании общего аккаунта квоту расходуют все пользователи вашего портала. [Условия OpenRouter](https://openrouter.ai/blog/tutorials/sillytavern-openrouter/).

При этом один вопрос пользователя может расходовать несколько запросов: например, переформулирование вопроса, генерация ответа и проверка ответа.

Можно рассмотреть следующие варианты:

| Вариант | Что доступно | Ограничения бесплатного использования |
|---|---|---|
| Локальные открытые модели | E5 для эмбеддингов, Qwen для LLM | Нет квоты внешнего провайдера; предел задаёт ваше железо |
| Groq | Облачные LLM с открытыми весами | Например, для `gpt-oss-20b`: 30 запросов/мин, 1000/сутки, также лимиты токенов. [Лимиты](https://console.groq.com/docs/rate-limits) |
| Google Gemini API | LLM и эмбеддинги | Есть бесплатный тариф; квоты зависят от модели и проекта. Gemini — закрытая модель. [Тарифы](https://ai.google.dev/gemini-api/docs/pricing), [квоты](https://ai.google.dev/gemini-api/docs/rate-limits) |
| Cloudflare Workers AI | LLM и эмбеддинги, включая multilingual BGE-M3 | 10 000 Neurons в сутки — единиц вычислений, не запросов. [Тариф](https://developers.cloudflare.com/workers-ai/platform/pricing/), [BGE-M3](https://developers.cloudflare.com/workers-ai/models/bge-m3/) |
| Hugging Face Inference Providers | Разные LLM и модели эмбеддингов | Бесплатному аккаунту сейчас выделяют $0,10 ежемесячно; для постоянной работы портала этого мало. [Тариф](https://huggingface.co/docs/inference-providers/pricing) |

Среди проверенных облачных вариантов нет бесплатного безлимитного API с гарантированным постоянным доступом. Регулярно обновляемая бесплатная квота подходит для разработки и небольшого MVP, но условия и доступные модели могут меняться.

Для вашего проекта я рекомендую два возможных режима.

Максимальная независимость: локальные [multilingual-e5-small INT8](https://huggingface.co/intfloat/multilingual-e5-small/tree/main/onnx) и [Qwen3-1.7B Q8_0](https://huggingface.co/Qwen/Qwen3-1.7B-GGUF). Платы за API нет, остаются электричество и обслуживание компьютера. На вашей текущей WSL-конфигурации это кандидаты для тестирования; скорость и качество ещё нужно измерить.

Практичный MVP с более сильной облачной LLM: локальные E5-эмбеддинги плюс Groq или Gemini на бесплатном тарифе. Обработка документов и поиск будут доступны независимо от облачной квоты; генерация ответов будет зависеть от неё. Для пользовательских документов нужно учитывать условия обработки данных: например, Google указывает использование данных бесплатного тарифа для улучшения продуктов. [Условия тарифа](https://ai.google.dev/gemini-api/docs/pricing).

Я бы сохранил эмбеддинги локальными с самого начала. Модель эмбеддингов должна быть одинаковой при индексации документов и поиске; её замена обычно требует пересчёта векторов. LLM можно менять отдельно, сохраняя существующий индекс. [Рекомендации по RAG](https://openrouter.ai/docs/guides/evaluate-and-optimize/rag).

### Пользователь

LLM можно менять отдельно, сохраняя существующий индекс.
Объясни что такое индекс.

### Ассистент — ответ

Индекс в вашем RAG — это подготовленные данные для поиска по документам.

Когда пользователь загружает документ:

1. Из документа извлекается текст.
2. Текст разбивается на небольшие фрагменты.
3. Модель эмбеддингов превращает каждый фрагмент в вектор — набор чисел, отражающий его смысл.
4. В PostgreSQL с pgvector сохраняются векторы, тексты фрагментов и ссылки на исходный документ.

Эту коллекцию подготовленных фрагментов и векторов я назвал индексом документов. Например:

| Фрагмент документа | Вектор |
|---|---|
| «Возврат товара возможен в течение 14 дней» | `[0.12, -0.34, …]` |
| «Доставка занимает от 3 до 5 дней» | `[0.56, 0.08, …]` |

Когда пользователь спрашивает «Какой срок возврата?», та же модель эмбеддингов преобразует вопрос в вектор. Система находит близкие по смыслу фрагменты и передаёт их LLM для составления ответа.

LLM можно заменить: новая модель получит уже найденные тексты, поэтому пересчитывать векторы не требуется.

При замене модели эмбеддингов векторы обычно нужно пересчитать: разные модели используют разные системы представления смысла, даже если длина векторов совпадает.

В строгом смысле у PostgreSQL ещё может быть отдельный индекс, например HNSW, который ускоряет поиск ближайших векторов. В предыдущем ответе я говорил о всей подготовленной поисковой базе документов.

### Пользователь

[@Context7](plugin://app-69ef18c674308191a2f952431f91ea61@openai-curated-remote) Возможно ли использование каких-то бесплатных API AI моделей для LLM?

### Ассистент — комментарий

Да, бесплатные API для LLM есть. Проверю через Context7 актуальные варианты и ограничения для вашего MVP.

### Ассистент — ответ

Да, бесплатные API для LLM можно использовать в вашем MVP, в том числе для китайских моделей. Проверил через Context7 и официальные страницы провайдеров. По состоянию на 2 октября 2026 года есть такие варианты:

| Модель | Где использовать | Бесплатный доступ |
|---|---|---|
| Qwen3.8-27B | Groq | Есть бесплатная квота; модель пока в статусе Preview. [Модель](https://console.groq.com/docs/model/qwen/qwen3.8-27b) |
| GLM-4.7-Flash | Напрямую через Z.ai | Входные и выходные токены указаны как бесплатные. [Тариф](https://docs.z.ai/guides/overview/pricing) |
| GLM-4.5-Flash | Напрямую через Z.ai | Также бесплатная генерация. [Тариф](https://docs.z.ai/guides/overview/pricing) |
| Ling 3.1 Flash | OpenRouter | Сейчас указана нулевая цена; действует доступность и ограничения OpenRouter. [Модель](https://openrouter.ai/inclusionai/ling-3.1-flash) |

У Qwen3.8-27B через Groq опубликованы следующие лимиты бесплатного плана: 30 запросов в минуту, 1000 в сутки, 8000 токенов в минуту и 200 000 токенов в сутки. Точные ограничения своего аккаунта нужно проверить в кабинете. [Лимиты Groq](https://console.groq.com/docs/rate-limits).

Для RAG лимит токенов может закончиться раньше лимита запросов: если вопрос вместе с найденными фрагментами, историей и ответом расходует 5000 токенов, то 200 000 токенов — примерно 40 таких обращений в сутки.

Последние флагманские модели не обязательно бесплатны:

- GLM-5.3 и GLM-5.3-Flash имеют платный API. Слово Flash само по себе не означает бесплатность. [Z.ai](https://docs.z.ai/guides/overview/pricing)
- DeepSeek-V4.1-Flash и DeepSeek-V4-Pro имеют платный официальный API. [DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/)
- Для новых Qwen через Alibaba Model Studio есть пробные квоты, но это ограниченный по времени доступ с условиями по региону и модели. [Условия](https://help.aliyun.com/en/model-studio/new-free-quota)

Для вашего MVP я бы первым протестировал Qwen3.8-27B через Groq и GLM-4.7-Flash напрямую через Z.ai, сравнив ответы по одним и тем же русскоязычным документам. Эмбеддинги оставил бы локальными.

LangGraph при этом работает на вашем backend и вызывает выбранную LLM через API. Сильная видеокарта для генерации ответов на вашей машине не потребуется. Бесплатность облачного API остаётся зависимой от квот и условий провайдера; качество этих моделей на ваших документах пока не проверено.

### Ассистент — комментарий

### Ассистент — ответ

Да, multilingual с поддержкой русского — обязательный критерий и для LLM, и для эмбеддингов. С учётом этого предыдущий список нужно уточнить:

| Модель | Что подтверждено | Решение |
|---|---|---|
| Qwen3.8-27B | Groq заявляет multilingual; отдельного подтверждения русского в проверенной карточке нет | Кандидат для проверки на русских документах. [Описание](https://console.groq.com/docs/model/qwen/qwen3.8-27b) |
| GLM-4.7-Flash | В официальной карточке указаны английский и китайский | Пока не рекомендую как основной вариант для русского. Это не доказывает, что модель не умеет русский. [Карточка](https://huggingface.co/zai-org/GLM-4.7-Flash) |

| Gemini | Русский явно включён в список поддерживаемых языков | Подходит по языковому требованию; есть бесплатный API с квотами. [Языки](https://ai.google.dev/gemini-api/docs/models/gemini?hl=en), [тарифы](https://ai.google.dev/gemini-api/docs/pricing) |

Для китайских моделей Qwen остаётся первым кандидатом: например, у семейства Qwen3.5 русский явно заявлен. Но переносить это подтверждение на любую новую версию автоматически нельзя. [Описание Qwen3.5](https://qwen.ai/blog?id=qwen3.5).

Для локальных эмбеддингов multilingual-e5-small подходит по заявленной поддержке русского. [Карточка модели](https://huggingface.co/intfloat/multilingual-e5-small).
