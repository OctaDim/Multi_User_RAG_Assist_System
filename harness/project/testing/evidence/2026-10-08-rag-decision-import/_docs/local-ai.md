# Локальные модели на CPU WSL и бесплатный fallback

Локальные измерения: 2026-10-02. Решение пользователя и обновление: 2026-10-03. Связанный документ: [архитектура](architecture.md).

## Выбранный принцип

**Утверждено пользователем для локального MVP:** `multilingual-e5-small` ONNX INT8 через ONNX Runtime CPU + `Qwen3.5-2B` GGUF Q4_K_M через llama.cpp CPU. Для LLM базовые настройки: `-t 4 -tb 8`, контекст запроса 4096, thinking выключен. Позднее пользователь установил 3 одновременные генерации по умолчанию, остальные в очередь; лимит читается из отдельного файла при запуске. Приведённые ниже замеры относятся к одному слоту. GLM-4.7-Flash оставлена для будущей проверки только при необходимости внешнего fallback.

LangGraph исполняется внутри локального backend. Инференс LLM — отдельный процесс llama.cpp с GGUF и `-ngl 0`. Эмбеддинги локальные: ONNX INT8 через ONNX Runtime либо GGUF через llama.cpp. FastAPI не выполняет тяжёлый синхронный инференс в event loop. Для ONNX потребуется ограниченный исполнитель; массовая индексация выполняется фоновым worker.

Если локальная генерация не проходит проверку времени или качества, меняется только LLM на разрешённый бесплатный API. Граф, состояние PostgreSQL, поиск и эмбеддинги остаются локальными. В этом режиме вопрос, выбранные фрагменты и необходимая часть истории передаются внешнему провайдеру.

## Обнаруженные ресурсы

- WSL2, x86_64; CPU AMD Ryzen 7 PRO 8845HS.
- Видимые WSL ресурсы: 8 логических CPU, топология 4 ядра × 2 потока.
- RAM: 5,6 GiB; в начале проверки доступно около 4,7 GiB; swap 9,8 GiB.
- Свободное место в файловой системе проекта: около 943 GiB.
- GPU не используется. Проверяется CPU-сборка llama.cpp `b11146`, commit `7fe450e19`, версия `0.5.0-dev`.

Это ресурсы текущего WSL, не вывод о полной физической памяти Windows. Размер файла модели не равен её RAM: дополнительно нужны контекст, вычислительные буферы, tokenizer и память остальных сервисов. Swap не считается запасом для интерактивной генерации. Одновременно тестируется одна LLM и одна модель эмбеддингов.

### Уточнённая нагрузка MVP

2026-10-03 пользователь задал 30 пользователей, до 10 одновременно, и включил OCR в MVP. Это требования к будущему сервису, а не проверенные показатели. Прежние замеры выполнены с одним слотом LLM без совместной нагрузки OCR, PostgreSQL, API и worker. Они не подтверждают десять параллельных генераций или приемлемую задержку для десяти одновременно пришедших вопросов.

Пользователь подтвердил отдельный конфигурационный файл с лимитом параллельных асинхронных генераций, применяемым при запуске: по умолчанию 3, остальные запросы в очередь. Это общий лимит сервиса, а не лимит каждого API-процесса. Конфигурация llama.cpp и объём контекста каждого запроса должны соответствовать выбранной параллельности. OCR и индексация требуют ограничений фоновой нагрузки и совместного измерения с тремя генерациями. Такие замеры ещё не выполнены. Выбранные E5 INT8 и Qwen3.5-2B Q4_K_M сохраняются; автоматический переход на внешнюю LLM или изменение квантования из нового требования не следует.

### Условия корректного сравнения эмбеддингов

- E5: запрос начинается с `query: `, документ — с `passage: `, в том числе по-русски. Используются masked mean pooling и L2-нормализация. Нарезка документа учитывает лимит 512 токенов вместе с префиксом и служебными токенами; тихое обрезание полного документа недопустимо.
- Qwen Embedding: instruction на стороне запроса, документ без него; `--pooling last`. Параметры именно embedding-модели нельзя переносить с chat-модели.
- В PostgreSQL фиксируются модель, ревизия, размерность и версия обработки. Векторы E5 и Qwen не смешиваются; смена embedding-модели требует отдельного индекса/набора векторов и переиндексации, даже при совпадении размерности. Смена LLM переиндексации не требует.

Источники: [обзор OpenRouter](https://openrouter.ai/blog/tutorials/free-llm-apis-compared/), [limits API](https://openrouter.ai/docs/api_reference/limits).

### Правила обработки ограничений для MVP

Это спецификация поведения будущего backend; обработчик внешних API ещё не реализован.

1. Разрешены только явно перечисленные бесплатные пары provider/model. Проверяется цена маршрута, включая дополнительные услуги. Нет автоматического перехода с `:free` на платный ID, платных плагинов или пополнения баланса. При изменении/неизвестности цены маршрут отключается.
2. Один общий ограничитель запросов на ключ провайдера и лимиты по пользователям. Считаются все обращения графа, включая переписывание запроса, резюме и retries. Несколько API-процессов используют общее состояние ограничителя.
3. Временный `429`, перегрузка или `5xx`: ограниченные повторы с backoff и jitter, соблюдение `Retry-After`/reset. Предлагаемый предел — не более двух повторов в пределах общего срока запроса. Если ожидание превышает срок, UI получает временную недоступность и время повторной попытки, когда оно известно.
4. Дневная квота, недостаток средств, истёкшая акция: не делать немедленные повторы; отключить маршрут до reset/изменения состояния. `401/403` и неверные параметры не лечатся повтором. У Z.ai HTTP `429` также означает недостаток баланса (`1113`); требуется разбор кода тела, а не один общий обработчик для всех `429`.
5. Ошибка посреди SSE означает незавершённый ответ, даже если HTTP был `200`. Частичный текст не сохраняется как успешная реплика. Перезапуск маркируется отдельно и не склеивается с ответом другой модели. Повтор использует ID операции, чтобы не дублировать пользовательское сообщение.
6. Когда бесплатные варианты недоступны: доступная локальная LLM либо явная временная ошибка. Нельзя выдавать отсутствие ответа провайдера за отсутствие информации в документах. Переключение между моделями не обходит общую дневную квоту OpenRouter.

Источники кодов и streaming-ошибок: [OpenRouter limits](https://openrouter.ai/docs/api_reference/limits), [Z.ai errors](https://docs.z.ai/api-reference/api-code).

## Метод локальной пробы

Скрипт [experiments/local_models.py](../experiments/local_models.py) запускает процессы на loopback с `-ngl 0`, четырьмя CPU-потоками и одним слотом генерации. Для LLM задаётся контекст 4096 и отключается thinking. Проверяются шесть синтетических русских документов/запросов, ответ по источнику, отсутствие сведений и уточняющий вопрос с историей. Записываются время первого текста, полное время ответа, token usage, RSS/high-water RSS и swap процессов.

Это небольшая проверка работоспособности. Она не измеряет качество на реальных PDF, большом корпусе, длинном контексте или одновременной работе нескольких пользователей. Отдельно потребуется нагрузка вместе с FastAPI, PostgreSQL и worker. Размеры весов и паспортные характеристики не выдаются за измеренную скорость.

При локальных пробах 2026-10-02 ключи внешних API отсутствовали. 2026-10-03 пользователь предоставил отдельный файл ключа Z.AI для ограниченной проверки; ключ не скопирован в исходники, документацию или результаты. OpenRouter и HF генерация не проверялись.

### GLM-4.7-Flash: отложенная проверка fallback

По указанию пользователя 2026-10-03 дальнейшие API-запросы остановлены. Модель не включается в локальный MVP. При необходимости fallback повторно проверить бесплатность нативного маршрута `https://api.z.ai/api/paas/v4/chat/completions`, затем сравнить `thinking.type=disabled` и `enabled` на русских сценариях с источниками, отсутствием ответа, историей и отвлекающим контекстом. Измерить время до пользовательского текста, общее время, качество и поведение при квотах; для thinking предусмотреть достаточный бюджет токенов.

Неполные наблюдения до остановки:

- Без thinking, максимум 192 токена: первая попытка завершилась тайм-аутом чтения 60 секунд; следующая — HTTP `429`, код `1302` (`Rate limit reached for requests`), без `Retry-After`. Успешного ответа в этом режиме не получено.
- С thinking, максимум 2048 токенов: один ответ по факту корректен — «По вторникам до 16:00 [D1].». Первый фрагмент рассуждения пришёл через 97,63 с, пользовательский текст через 103,59 с, полный ответ за 103,62 с. Usage: 146 входных и 476 выходных токенов, из них 462 reasoning. Следующий запрос прерван при остановке пробы.
- Это не завершённое сравнение режимов и не основание для оценки типичной скорости или общего качества модели. Причину долгого ожидания и точную квоту аккаунта не установили. Код `1302` отличается от ошибки баланса `1113`; пополнение не выполнялось.

Сохранены [тайм-аут](benchmarks/zai-glm-47-flash.json), [ограничение API](benchmarks/zai-glm-47-flash-retry.json), [частичный результат thinking](benchmarks/zai-glm-47-flash-thinking.json). Скрипт для будущей пробы: [zai_probe.py](../experiments/zai_probe.py), параметры `--thinking disabled|enabled`, `--max-tokens`, `--timeout`, `--key-file`, `--output`. Скрипт не запускает повторов автоматически и не переключается на платные модели. Обработка незавершённого SSE проверяется локально командой `python3 experiments/zai_probe.py --self-check`.

Документация: [прайс Z.AI](https://docs.z.ai/guides/overview/pricing), [thinking и API](https://docs.z.ai/api-reference/llm/chat-completion), [коды ошибок](https://docs.z.ai/api-reference/api-code).

## Измеренные результаты

Все приведённые ниже запуски — CPU, одна LLM, один слот, контекст 4096, thinking выключен. Базовые пробы используют 4 потока генерации и 4 обработки prompt (`-t 4 -tb 4`); другие настройки указаны отдельно. Время первого текста отсчитывается от локального HTTP-запроса; короткие запросы после первого используют часть prompt cache. В длинной пробе тот же целевой факт помещён между 25 отвлекающими фрагментами. Текст для LLM одинаков, число токенов различается из-за tokenizer. Это единичные пробы, не p95 и не нагрузочный тест.

| Связка | Генерация коротких ответов | Короткие сценарии | Длинный контекст |
| --- | --- | --- | --- |
| Qwen Embedding Q8 + Qwen3.5-2B Q4_K_M | 16,3–16,7 токена/с; полные ответы 1,9–2,9 с | Факт, отсутствие сведений, уточнение — пройдены | Не запускался в этой связке |
| E5 INT8 + Qwen3-1.7B Q8_0 | В повторной пробе 10,9–11,9 токена/с; полные ответы 0,85–3,94 с | Все три пройдены | **Не пройден:** на 1481 входном токене ответила «нет информации», хотя факт присутствует; первый текст 11,61 с |
| E5 INT8 + Qwen3.5-2B Q4_K_M | 15,7–15,8 токена/с; полные ответы 2,04–3,19 с | Все три пройдены | **Пройден:** 1308 входных токенов, первый текст 11,06 с, полный ответ 12,53 с |
| E5 INT8 + Qwen3.5-2B Q4_K_M, `-t 8 -tb 8` | 14,4–15,2 токена/с; полные ответы 1,88–2,87 с | Все три пройдены | **Пройден:** первый текст 8,31 с, полный ответ 9,91 с |
| E5 INT8 + Qwen3.5-2B Q4_K_M, `-t 4 -tb 8` | 15,7–17,0 токена/с; полные ответы 1,75–2,64 с | Все три пройдены | **Пройден:** первый текст 7,62 с, полный ответ 9,11 с |
| E5 INT8 + Qwen3-4B Q4_K_M, `-t 4 -tb 8` | 8,6–9,1 токена/с; полные ответы 1,08–4,29 с | Все три пройдены | **Пройден:** 1481 входной токен, первый текст 15,51 с, полный ответ 17,55 с; обнаружен swap E5 |

E5 и Qwen Embedding нашли правильный документ первым в 6/6 простых русских запросов. В первой пробе медиана embedding-запроса E5 была 3,4 мс, Qwen — 61,9 мс. E5 вызывалась в Python, Qwen — через loopback HTTP: это измерение двух вариантов интеграции, а не изолированный benchmark ядер моделей. Равный результат 6/6 не доказывает равное качество на сложном корпусе.

Память процессов: E5 вместе с Python/ONNX — около 0,46 GiB RSS, максимум около 0,48 GiB; Qwen Embedding — около 0,92 GiB. Qwen3.5-2B — 1,81–2,06 GiB RSS в выполненных пробах. Qwen3-1.7B после длинной пробы — около 2,25 GiB. В этих связках у измеренных процессов `VmSwap=0`.

**4B не проходит ресурсный отбор для текущих 5,6 GiB WSL:** пик процесса LLM — 4,21 GiB, итоговый RSS — 3,89 GiB; у E5 обнаружено около 180 MiB swap. При этом FastAPI, PostgreSQL и worker ещё не запущены. Значит, успешная загрузка 2,50-ГБ GGUF не доказывает пригодность связки для MVP. Вернуться к 4B можно после увеличения доступной WSL RAM с учётом памяти Windows и повторного общего нагрузочного теста; конфигурация WSL в этой сессии не менялась. Системный swap также стал ненулевым в ходе загрузок/проб; его нельзя смешивать с показателем отдельного процесса.

Сырые результаты: [Qwen Embedding + 2B](benchmarks/qwen-embedding-qwen35-2b-q4.json), [E5 + 1.7B](benchmarks/e5-qwen3-17b-q8.json), [E5 + 2B, 4/4 потока](benchmarks/e5-qwen35-2b-q4.json), [8/8 потоков](benchmarks/e5-qwen35-2b-q4-t8.json), [4/8 потоков](benchmarks/e5-qwen35-2b-q4-t4-tb8.json), [E5 + 4B](benchmarks/e5-qwen3-4b-q4.json). Ревизии, SHA256 и версии runtime: [manifest.json](benchmarks/manifest.json). Проверка 1.7B намеренно завершилась ненулевым кодом после отрицательного результата длинного сценария; ошибка сохранена, результат не скрыт повторным подбором prompt. Функциональные assertions 4B пройдены, но её ресурсная оценка отрицательная по сохранённым метрикам.

Рекомендация по выполненным пробам: **E5 INT8 + Qwen3.5-2B Q4_K_M, llama.cpp `-t 4 -tb 8`, один слот в измерении, контекст 4096, thinking выключен.** Из трёх проверенных LLM она дала лучший баланс скорости, памяти и результата данного длинного сценария. Это рекомендация по этим измерениям, не заявление о превосходстве на любых задачах. Утверждённый позднее лимит MVP — 3 одновременные генерации — отдельно ещё не проверен. Qwen3-1.7B Q8_0 работает с короткими запросами, но не прошла весь набор. Qwen3-4B Q4_K_M прошла проверку ответов, однако медленнее и вызывает давление на память. Пока нет оснований считать всю локальную генерацию непригодной и обязательно переходить на внешний API.

Проба подаёт синтетические фрагменты и историю непосредственно в модель. Она не проверяет PostgreSQL/pgvector, LangGraph, сохранение checkpoint, авторизацию пользователей или реальные PDF — эти части зафиксированы в архитектуре и ещё не реализованы.

## Повторение пробы

Весовые файлы, CPU-сборка и Python-окружение находятся в `/tmp/rag-model-probe`; это временное место, файлы могут исчезнуть после очистки или перезагрузки. Модели не включаются в исходники проекта. Для повторной загрузки используются `hf download`, точные repo/revision/file из manifest; после загрузки SHA256 сверяется с manifest.

```bash
/tmp/rag-model-probe/venv/bin/python experiments/local_models.py \
  --server /tmp/rag-model-probe/runtime/llama-b11146/llama-server \
  --embedding-backend e5-onnx \
  --embedding-model /tmp/rag-model-probe/models/e5 \
  --llm-model /tmp/rag-model-probe/models/Qwen3.5-2B-Q4_K_M.gguf \
  --threads 4 --batch-threads 8 --long-context \
  --output _docs/benchmarks/e5-qwen35-2b-q4-t4-tb8.json
```

Скрипт прекращает запуск LLM, если после загрузки эмбеддингов доступной RAM меньше размера GGUF плюс 1,5 GiB на runtime и запас системы. Это предварительная оценка для одного слота/контекста 4096, не гарантия пикового потребления. Сервисы самого портала во время пробы не запущены.
