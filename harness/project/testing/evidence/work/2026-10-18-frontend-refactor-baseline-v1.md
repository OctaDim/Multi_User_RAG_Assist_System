# Исходная проверка фронтенда перед рефакторингом

Дата создания: 2026-10-18. Статус: завершённая исходная проверка; рефакторинг не реализован и не принят. Источник: HEAD `9f3d77cbd4ea4710f918be41679b5ffc0ed45dad`, исходники приложения без изменений.

## Реальные браузерные сценарии

Команда из корня проекта:

```text
backend/.venv/bin/pytest backend/tests/browser/test_accounts.py backend/tests/browser/test_documents.py::test_ui_smtp_original_text_correction_and_delete -q
```

Результат: `1 failed, 4 passed in 66.28s`. Все четыре сценария аккаунтов прошли. Документ не стал готовым за 20 секунд: отдельно запускаемый worker завершился с `KeyError: 'RAG_E5_DIR'`. Первоначальная команда не передала ему необходимый путь модели.

Повторён только упавший сценарий. Существующий `load_service_config()` прочитал настройки установки; `section_path()` сформировал пути `RAG_E5_DIR`, `RAG_MODEL_PATH`, `RAG_OCR_DIR`, `RAG_OCR_MODEL_PATH`; значения переданы дочернему pytest без вывода настроек/секретов и без записи конфигов. PostgreSQL, аккаунты, почтовый сервис, оригиналы и API остаются изолированными тестовыми fixtures.

```text
backend/.venv/bin/pytest backend/tests/browser/test_documents.py::test_ui_smtp_original_text_correction_and_delete -q
```

Результат повтора: `1 passed in 9.66s`. Проверены настоящий UI, регистрация/SMTP/email verification/вход, загрузка TXT и E5-обработка, открытие, отсутствие выполнения HTML из документа, скачивание неизменённого оригинала, исправление/переиндексация и удаление. PDF/OCR и генерация в этом запуске не проверялись.

## Воспроизведение отказа кнопки остановки

Существующий Playwright/Chromium открыл исходный фронт с тестовыми сетевыми ответами. Тестовая история содержала один запрос в состоянии `generating`. POST `/api/answers/audit-request/stop` возвращал контролируемый 503 с `request_failed`; реальные аккаунты и запросы не использовались.

```text
Controlled 503 on POST /answers/audit-request/stop; no real account/request mutated.
After failure, stop disabled: True
UI state: Проверочный вопрос / Ответ формируется / Ответ модели /
          Проверка отказа остановки. / Остановить ответ
Page errors: []
```

До нажатия кнопка была enabled, после ошибки появилось «Не удалось выполнить действие.», но повторное нажатие блокировалось. Причина в исходном `frontend/src/conversations.js`: обработчик `stop.onclick` устанавливает `stop.disabled = true`, но не снимает блокировку при ошибке; render обновляет `hidden`, не `disabled`. Это воспроизведённый дефект, исправление ещё не выполнено.
