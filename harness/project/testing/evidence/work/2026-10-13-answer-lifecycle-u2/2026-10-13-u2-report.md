# U2: атомарный приём, история и настройки

Создано: 2026-10-13. Статус: локальная проверка U2 пройдена; полный lifecycle
не завершён. Источник — U2/KTD1/KTD2/KTD5 плана
`harness/project/docs/plans/2026-10-13-0244-feat-rag-answer-lifecycle-plan.md`.

Реализованы контролируемая миграция, асинхронный DB pool FastAPI lifespan,
аутентификация по сохранённой серверной session с текущей проверкой аккаунта,
owner/role boundary, общий admit/read/stop, журнал событий и настройки с аудитом.
В production нет test credentials, fixture principals или создания готовых
документов через обходной API. Выпуск sessions, подтверждение email и publisher
целых ревизий принадлежат зависимым областям и ещё не реализованы — G3/G4 открыты.

## Проверки

```sh
uv run --project backend --frozen --cache-dir /tmp/rag-answer-lifecycle-uv-cache pytest -c backend/pyproject.toml backend/tests/test_resources.py backend/tests/test_admission.py backend/tests/test_settings.py backend/tests/test_http.py -q -s
```

[Окончательный результат](admission-green-v5.txt): 26 passed, 6.81 секунды.
Каждый DB-тест использует отдельную временную базу настоящего PostgreSQL;
сервер получен из pgserver wheel через uv и прекращён fixture cleanup.
Два конкурирующих admit используют разные PostgreSQL connections/PIDs.
[Фактические версии](environment-v1.json) и исходные установки
[runtime dependencies](dependencies-v1.txt), [test dependencies](test-dependencies-v1.txt),
[пакет app](package-install-v1.txt) сохранены отдельно.

Проверены один незавершённый запрос, owner+operation uniqueness самой БД,
idempotency потерянного ACK, конфликт payload, заново заблокированный владелец,
отсутствие ready sources без побочных записей и позднего auto submit,
чужие user/admin и административное чтение super_admin, anonymous/expired
session и verified/active/disabled state, полный rollback при ошибке события,
отказ при отсутствии живого coordinator lease. История проверена новым DB
connection и HTTP snapshot; stop не создаёт пустое assistant-сообщение.
Для MVP paid=false не запрещает доступ.

Настройки: только super_admin, только max_active/step_width, положительные
целые значения без bool; restart-only и неизвестные поля отклоняются.
Переопределения и revision сохраняются после повторной миграции и закрытия/
повторного открытия FastAPI lifespan/DB pool. applied_revision остаётся 0:
координатор U4 ещё не реализован, сохранение не объявляется применением лимита.
Native диапазоны и подтверждение применения также завершаются в U4.

[Первый RED](admission-red-v1.txt) наблюдал отсутствие app до реализации;
[первый GREEN](admission-green-v1.txt) содержит 19 passed. Дополнения HTTP,
DB constraints и restart gates записаны отдельными прогонами
[v2](admission-green-v2.txt), [v3](admission-green-v3.txt), [v4](admission-green-v4.txt).

## Установленный пакет

Manifest устанавливает app и регистрирует rag-api, rag-migrate, rag-generation.
API help проверен командой `uv run --project backend rag-api --help`.
Миграционный entrypoint вызывает тот же migrate, что DB fixtures; setup
AsyncPostgresSaver выполняется отдельно от API startup. Generation entrypoint
реализуется в U4, сейчас вызов rag-generation ещё не является рабочим запуском.
Совместный запуск нескольких процессов по G5 проверяется в U8.

Wheel собран и установлен в отдельный /tmp target. [Первая сборка](wheel-build-v1.txt)
и [RED установки](wheel-layout-red-v1.txt) выявили выбор чужого соседнего config:
resource_path сначала проверял родителя app вместо встроенных _resources.
Добавленный regression test тоже показал [RED](resource-red-v1.txt).
Узкая правка предпочитает собственные packaged resources, сохраняя source-tree
fallback. [Повторная сборка](wheel-build-v2.txt) и [GREEN установленного wheel](wheel-layout-green-v1.txt)
подтвердили загрузку собственных defaults и миграций даже при чужом config рядом.
Ошибка исправлена в рамках U2, без отдельного shipping или изменения product contract.

## Упрощение и ограничения

Три read-only reviewer проверили reuse, quality и efficiency по ce-simplify-code.
Применены: reuse общего SHA256 helper; перенос bearer в auth, устранение
дублирования revision; два индекса, соответствующих фильтру и порядку history.
Hashing в test fixtures оставлен независимым oracle. Более широкий refactor
рендеринга settings row пропущен в пользу меньшей правки.
Применено reuse=1, quality=2, efficiency=2; пропущено 2 предложения.
Performance эффект индексов не измерялся. Миграция 001 ещё не применялась к
постоянной прикладной БД; временные test databases удалены. Последующие
изменения схемы должны быть отдельными миграциями, не правкой applied 001.

Syntax compileall и whitespace прикладных изменений прошли. Отдельные lint/
typecheck в проекте приложения не настроены. Raw logs неизменны; их whitespace
не очищается. Политики настоящих SSE/reconnect/checkpoint operations,
physical native reservations, source invalidation и transport barrier остаются
U3–U8. Unit checks с test аккаунтами/документами не снимают G3–G5.
