# Evidence operations

- Authorized work permits new work reports/results and additions to the current
  unfinished report directly, without another inbox request or per-file confirmation.
  Mechanism evidence uses the authorized inbox route: project/inbox or common/inbox.
  No repeated approval for an already authorized unchanged stage.
- A report is completed when the reported task/result is finished or explicitly
  closed; failed verification can also be final. Age/path/absence of a status
  does not establish completion. A current open task permits current-report additions,
  never retroactive edits to previous runs.
- Correct a completed report only by a NEW creation-dated addendum linking the
  original, through inbox for mechanism evidence. Preserve the original bytes.
- Raw logs/snapshots are immutable in both categories, including within inbox;
  a new run uses a NEW file. Keep raw results separate from editable current reports.
- Deletion/move/rename needs separately agreed named contents, old/new paths,
  dependent links and consequences; mechanism operations also need the inbox route.
  Preserve provenance, hashes and proven creation dates; age never grants cleanup.

Protected changes outside inbox retain workflow's separate direct-bypass question
and unequivocal answer; tools/scripts/other agents are no exception. Ordinary
work-save authority grants no migration or mechanism write. Preserve actual
failed/unrun/passed and agent statuses; copying/permission never upgrades them.
These are behavioral instructions, not filesystem enforcement.
