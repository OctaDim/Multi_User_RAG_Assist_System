# Author one instruction

Use using-superpowers before authoring. Establish task, useful result, intended
harness and destination; cwd is not proof. Before design/substantial edits read
[content](references/content-contract.md).

1. Inspect existing owners/rules/resources/checks; select by independent result,
   not theme or old name. Already covered → no new record.
2. Produce inputs → actions → result → observable completion, with limits,
   approvals/stops/missing data and exact tested conditions for resource reading.
3. Before writing follow the authorized inbox route from root
   `harness/common/skills/comm-process-harness-inbox/SKILL.md`; keep a full dated
   candidate and permanent rationale/evidence outside working instructions.

Done: compact complete candidate preserving every contract and both-mode
dependencies. Design alone is not validation or publication. When checking is
requested use `harness/common/skills/comm-validate-harness-instructions/SKILL.md`;
when publishing use `harness/common/skills/comm-publish-harness-instructions/SKILL.md`.
Do not load these stages for an unrelated request. Protected entrypoints and
canonical priority remain mandatory.
